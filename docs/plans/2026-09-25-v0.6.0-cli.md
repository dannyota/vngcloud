# v0.6.0 First CLI Release Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Tasks run in order; one final review after the last code task, adversarial for credential file writes, `--debug`, the `--yes` guard, and read-only profiles. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship the `vngcloud` command: `configure`, `version`, `--output json|table|text`, `--query`, stable errors and exit codes, read-only profiles, generated reference docs, and commands for `billing`, `pricing`, `compute`, `network`, and `dns`.

**Architecture:** `cmd/vngcloud/main.go` calls `internal/cli.Main`. `internal/cli` (one package, one file per service, no subpackages) builds a cobra root, one command per service from a typed operation table, and one per operation. It uses only the public SDK. Task 1 is an SDK change; every other task is CLI code.

**Tech Stack:** Go 1.27.1; CLI-only dependencies (standing owner approval, vetted 2026-09-25, no known vulnerabilities): `github.com/spf13/cobra` v1.10.2 (commands; brings `spf13/pflag`, and `inconshreveable/mousetrap` on Windows), `github.com/jmespath/go-jmespath` v0.4.0 (`--query`, standard JMESPath as in the AWS CLI, no further deps), `golang.org/x/term` v0.46.0 (hidden secret input; brings `golang.org/x/sys`).

**Spec (approved):** `docs/design/cli.md` (the whole CLI, including exit codes, error classes, read-only, debug, configure file writes); `docs/design/sdk-and-cli.md` "Errors", "Logging", "Testing", "Docs"; `docs/design/billing.md` "CLI" and "`cli.Write` and `cli.Destructive`"; `docs/adr/0002-write-api-conventions.md`. Design wins over this plan.

## Global Constraints

- Branch `v0.6.0` from `master`. Workers may make one signed commit per task when their brief allows; nobody disables signing.
- Every task passes `make check`, `go vet -tags live ./...`, `go vet -tags livewrite ./...`, `GOOS=windows go vet ./...`, `GOOS=darwin go vet ./...`, and `bash scripts/check-sdk-deps.sh` (Task 2 adds it; before then, skip).
- `internal/cli` imports only public SDK packages, never `internal/...`.
- Nothing prints, logs, or returns a password, TOTP secret, token, authorization code, cookie, root email, `Authorization` header, or Input values of write operations. Tests assert this with marker values.
- Nothing waits for input it may never get: no prompt without a terminal, no unbounded stdin read.
- Tests run the root command in-process with a test-only config hook (Task 2) that points every endpoint at `httptest` and installs an HTTP transport that fails any non-loopback host. Tests set `HOME` and `USERPROFILE` to temp dirs and unset every `VNGCLOUD_*` variable found in `os.Environ()`. No test reads the real home or `.env`.
- No plan or task IDs in code, comments, or tests. No em dashes. Name the platform GreenNode in docs.

## Review Focus (adversarial)

- No secret or account data in `--debug`, errors, or generated docs.
- `configure` writes follow `docs/design/cli.md` "File writes" exactly (regular-file check on the open handle, symlink resolution with dangling links refused, temp file removed on failure, modes at creation) and edit the line the SDK actually reads.
- Destructive and read-only refusals happen before a client is built; no flag, env casing, or `configure set` call can turn read-only off.
- Exit codes for every class, including cancellation during login, and cobra's own errors.
- No Input field flag shadows a global flag; `--enabled false` cannot mean true.

### Task 0: Dependencies (manager)

- [ ] `go get github.com/spf13/cobra@v1.10.2 github.com/jmespath/go-jmespath@v0.4.0 golang.org/x/term@v0.46.0`, `make vuln`, commit `build: add cobra, go-jmespath, and x/term for the CLI`. After Task 2 imports them, run `go mod tidy` and commit so none stays `// indirect`.

### Task 1: SDK errors, `LoginError`, logging, `ProfileSetting`

**Files:** `internal/core/errors.go`, `internal/core/client.go`, `internal/core/auth.go`, `internal/core/load.go`, `internal/core/config.go`, `internal/transport/transport.go`, `internal/iamuser/login.go`, their tests, `vngcloud.go`, and a new `docs/wiki/Errors.md` (plus `_Sidebar.md`, `Configuration.md`).

- `APIError.Code`: the API's code wins, except an envelope code equal to the HTTP status, which counts as none. With none, use the design's status table (400 `BadRequest`, 401 `Unauthorized`, 403 `Forbidden`, 404 `NotFound`, 409 `Conflict`, 429 `Throttled`, 5xx `ServerError`, other 4xx `ClientError`). The billing `NotFound` mapping still wins. No status keeps an empty code.
- `*LoginError{Status int; CaptchaSuspected bool; Reason string; Err error}`: `Reason` is fixed text per failure step; `Err` is `ErrAuth`, or `ctx.Err()` when the context ended, never the raw iamuser error (its text can hold the token response body and full URLs). `CaptchaSuspected` is true when the sign-in form is shown again after a submit. Root re-exports it.
- `WithLogger`: wire the stored logger into the transport. One Debug record named `request` per attempt with `method`, `path` (no query), `status` (omitted when there is no response), `duration`. IAM login logs `login started` and `login finished` with `ok`. Nothing else.
- `Config.ProfileSetting(key string) string`: a config-file key of the profile `LoadConfig` resolved; empty for `NewConfig`.
- [ ] Tests first: every status class; API code wins; envelope code equal to status falls back; `LoginError` for each failure with markers in username, password, TOTP code, authorization code, and token response body absent from `err.Error()` and from every wrapped error; login cancelled gives `errors.Is(err, context.Canceled)`; a slog capture sees exactly the fields above and no query string or header; `ProfileSetting` returns `output` and `read_only`. Commit `feat(errors): add status-derived codes, LoginError, debug request logs, and ProfileSetting`.

### Task 2: CLI root, test hook, errors, exit codes, `version`, read-only

**Files:** `cmd/vngcloud/main.go`; `internal/cli/{main.go,root.go,config.go,errors.go,version.go,readonly.go}` and tests; `scripts/check-sdk-deps.sh` (manager-owned path; the brief assigns it): fails when any package from `go list ./...` other than `cmd/...` and `internal/cli` depends on cobra, pflag, jmespath, or `x/term`, using `go list -deps`, and exits 0 when clean.

- `cli.Main(ctx, args, stdin, stdout, stderr) int` builds a fresh root per call. `main` cancels ctx on the first SIGINT or SIGTERM and restores default handling after it, so a second signal exits even during a blocking password read.
- An unexported `testOptions` hook (set only from `_test.go` in package `cli`) adds `vngcloud.LoadOption`s such as `WithEndpointOverrides` and `WithHTTPClient` to every Config the CLI builds.
- Root: `SilenceErrors` and `SilenceUsage`; `SetFlagErrorFunc` and `Args` validators return a usage error type; unknown commands are usage errors; cobra's default `completion` command is disabled. Every operation command uses `Args: cobra.NoArgs`.
- Global flags: `--profile`, `--region`, `--project-id`, `--output`, `--query`, `--yes`, `--debug`, `--read-only`. Config per `docs/design/cli.md` "Building the Config", with `WithTokenCache(<home>/.vngcloud/cache)`; `--output` defaults to `cfg.ProfileSetting("output")`, else `json`.
- Read-only: on when `--read-only`, `VNGCLOUD_READ_ONLY`, or the profile's `read_only` is `1` or `true`; `0`, `false`, or empty is off; any other value is a config error. Flag and env are checked before `LoadConfig`, the profile right after. Each source can only turn it on.
- Errors to stderr as one JSON line per `docs/design/cli.md`, with the classes it names for non-API errors (`InvalidUsage`, `ReadOnly`, `InvalidConfig`, `NoCredentials`, `LoginFailed`, `RequestFailed`); an `*APIError` with no code and no status is `RequestFailed`. Exit codes, checked in this order: `context.Canceled` or `DeadlineExceeded` anywhere in the chain gives 1; `ErrNoCredentials`, `ErrCredentialsFile`, `*LoginError`, `ErrAuth` give 3; `IsNotFound` gives 4; usage errors, `ErrInvalidInput`, `ErrInvalidConfig`, `ErrProjectAmbiguous`, missing `--yes`, read-only refusal, `--query` compile errors, and an unsafe token cache dir give 2; everything else 1.
- `vngcloud version`: module version from `debug.ReadBuildInfo` (or `(devel)`), Go version, OS/arch.
- [ ] Tests first: each exit code, including login cancelled (1) and a cobra flag error (2, one JSON line, no usage text); error JSON shape; the non-loopback transport refuses a real host; `--debug` stderr has method, path, status, and no markers; read-only precedence and bad values; `version`. Commit `feat(cli): add the vngcloud command root, errors, and exit codes`.

### Task 3: Typed operation tables and flags

**Files:** `internal/cli/{op.go,flags.go,names.go,input.go}` and tests.

- `type Op[C any]`; `cli.Read[C, In, Out any](name string, m func(*C, context.Context, *In) (*Out, error)) Op[C]`; `cli.Write(...)` with `cli.Destructive()`; `cli.Service[C any](name string, newClient func(vngcloud.Config) *C, ops ...Op[C])`. The compiler rejects an op from another client type.
- Names (`names.go`): kebab-case where a run of capitals followed by a lowercase letter gives its last capital to the next word (`VirtualIPAddressID` to `virtual-ip-address-id`, `ListVPCs` to `list-vpcs`, `ListSSHKeys` to `list-ssh-keys`, `ListOSImages` to `list-os-images`, `ListWANIPs` to `list-wanips`). One shared rename table holds exceptions: flag `VPCID` to `--vpc-id`, and `Query` (billing cost operations) to `--search`. A test fails when any Input field's flag equals a global flag, and when any operation name differs from the kebab form of its method outside the table.
- Flags: exported fields of types `string`, `int`, `int64`, `bool`, `*string`, `*int`, `*int64`, `*bool`. Every field is applied only when its flag is `Changed`, after `--cli-input-json` (`'<json>'` or `file://path`, Go field names, unknown keys are usage errors, file read capped at 1 MiB). Other types (such as `map[string]any`) only through `--cli-input-json`. After the merge the CLI checks `vngcloud:"required"` fields and returns a usage error naming the flag, so `--cli-input-json` can supply them.
- `Write`: `--debug` logs `write started` and `write finished` with only the operation name; with `Destructive`, refuse without `--yes`; under read-only, refuse. Both before building a client.
- [ ] Tests first against a fake service and `httptest`: names and renames; `--enabled=false` sends false and `--enabled false` exits 2; JSON then flag merge where an unset flag leaves the JSON value; required after merge; `file://` and its size cap; unknown JSON key; destructive and read-only refusals with zero requests. Commit `feat(cli): build operation commands from SDK Input structs`.

### Task 4: Output

**Files:** `internal/cli/{encode.go,query.go,render.go}`, tests, `internal/cli/testdata/golden/`.

- Encoder: reflection over the Output; structs become objects keyed by Go field names in declaration order; embedded structs flatten like `encoding/json`; JSON tags ignored; unexported fields skipped; maps with keys sorted; `any` values encoded by their dynamic type; nil pointers `null`, nil slices `[]`; `time.Time` RFC 3339.
- `--query`: encode to JSON bytes, decode into `any` (numbers become `float64`, which go-jmespath needs), then search; objects after a query print with sorted keys. A compile error is a usage error. A runtime query error after a successful write prints the error with class `QueryFailed`, exit 1, and states that the write succeeded.
- `json` prints indented JSON; `text` and `table` per `docs/design/cli.md` "Output", sorted keys.
- [ ] Golden tests for each format on a paged list, a get, a nested object, an embedded struct, `any` fields, nulls, a numeric filter (`[?LimitAmount > \`100\`]`), and a projection; `-update` regenerates. Commit `feat(cli): add json, text, and table output with --query`.

### Task 5: Service tables

**Files:** `internal/cli/{svc_billing.go,svc_pricing.go,svc_compute.go,svc_network.go,svc_dns.go}` and tests.

- Every operation of the five packages. Kinds per `docs/design/billing.md` "CLI": `delete-budget` and `delete-budget-threshold` are `Write` plus `Destructive`; other creates and updates are `Write`; `pricing get-quote` is `Read`; everything named `Get` or `List` is `Read`.
- [ ] Tests: every op not named Get or List is a Write, and `get-quote` is the only Read that sends POST; each service's help lists its ops; one read per service against a fixture-backed server prints golden JSON; `billing delete-budget` without `--yes` exits 2 with zero requests; `billing update-budget --budget-uuid b --status PAUSED` sends only `status`; `billing get-cost-overview --search x --query Summary` sends `q=x` and filters. Commit `feat(cli): add billing, pricing, compute, network, and dns commands`.

### Task 6: `configure`

**Files:** `internal/cli/{configure.go,configfile.go}` and tests.

- Refusals: `configure` and `configure set` exit 2 under `--read-only` or `VNGCLOUD_READ_ONLY`; `configure set read_only` refuses to turn it off for a profile that has it on. `get` and `list` always work and mask `password` and `totp_secret`.
- `vngcloud configure`: needs a terminal on stdin, else exit 2 naming `configure set`. Prompts show non-secret defaults and secrets as `****`; secrets read with `term.ReadPassword`.
- `configure set <key> <value>`; `configure set <key> -` reads at most 4 KiB from stdin and refuses when stdin is a terminal (use `configure` instead). `password` and `totp_secret` accept only `-`. Values of `read_only` (`true`, `false`, `1`, `0`) and `output` (`json`, `table`, `text`) are validated.
- File writes exactly as `docs/design/cli.md` "File writes": resolve symlinks and refuse a dangling one; open an existing target non-blocking and require a regular file from the open handle; a missing parent of an env-named path is an error; create `~/.vngcloud` 0700; write `os.CreateTemp` in the resolved directory with 0600, `Sync`, `Close`, `Rename`; remove the temp file on every failure. Edit lines in place: match section names as the SDK parser trims them and keys case-insensitively, change the last occurrence (the one the SDK reads), keep comments and other sections. Concurrent `configure set` runs are last-writer-wins; document it.
- [ ] Tests first: `set` then `LoadConfig` reads it back; duplicate sections, duplicate keys, and `Read_Only` casing edit the effective line; symlink stays a symlink; dangling symlink and FIFO refused (skip FIFO on Windows); modes; literal password refused and file unchanged; `-` from a pipe; `-` from a terminal refused; no terminal means exit 2 with zero writes; read-only refusals; masking with markers. Commit `feat(cli): add configure for profiles and credentials`.
