# v0.6.0 First CLI Release Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Tasks run in order; one final review after the last code task, adversarial for credential file writes, `--debug`, the `--yes` guard, and read-only profiles. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship the `vngcloud` command: `configure`, `version`, `--output json|table|text`, `--query`, stable errors and exit codes, read-only profiles, generated reference docs, and commands for `billing`, `pricing`, `compute`, `network`, and `dns`.

**Architecture:** `cmd/vngcloud/main.go` calls `internal/cli`. `internal/cli` builds a cobra root command, one subcommand per service from an operation table, and one per operation. It uses only the public SDK. Task 1 is an SDK change (error codes, `LoginError`, debug logging); every other task is CLI code.

**Tech Stack:** Go 1.27.1; CLI dependencies approved by the owner on 2026-09-25: `github.com/spf13/cobra` v1.10.2 (plus `spf13/pflag`, and `inconshreveable/mousetrap` on Windows), `github.com/jmespath/go-jmespath` v0.4.0, `golang.org/x/term` v0.46.0 (plus `golang.org/x/sys`). The SDK packages import none of them.

**Spec (approved):** `docs/design/cli.md` (the CLI: dependencies, commands, flags, output, errors and exit codes, read-only, debug, configure); `docs/design/sdk-and-cli.md` sections "Errors", "Logging", "Testing", "Docs"; `docs/design/billing.md` sections "CLI" and "`cli.Write` and `cli.Destructive`"; `docs/adr/0002-write-api-conventions.md`. Design wins over this plan.

## Global Constraints

- Branch `v0.6.0` from `master`. Workers may make one signed commit per task when their brief allows; nobody disables signing.
- The manager adds the three dependencies to `go.mod`/`go.sum` (`go get` at the exact versions above) in its own commit before Task 2, and runs `make vuln`.
- Every task passes `make check`, `go vet -tags live ./...`, `go vet -tags livewrite ./...`, `GOOS=windows go vet ./...`, `GOOS=darwin go vet ./...`, and `go list -deps ./billing/... ./pricing/... ./compute/... ./network/... ./dns/... . | grep -E 'cobra|jmespath|x/term'` prints nothing.
- `internal/cli` imports only the public SDK packages, never `internal/core` or other SDK internals.
- Nothing prints, logs, or returns a password, TOTP secret, token, authorization code, cookie, root email, or `Authorization` header. Tests assert this with marker values.
- Nothing prompts when stdin is not a terminal; the command exits with code 2 instead. No command can wait for input an agent cannot give.
- Tests run the root command in-process against `httptest` servers with `HOME`, `USERPROFILE`, and every `VNGCLOUD_*` variable set by the test. No test reads the real home directory or `.env`, and no unit test reaches the network.
- No plan or task IDs in code, comments, or tests. No em dashes. Name the platform GreenNode in docs.

## Review Focus (adversarial)

- `--debug` output and every error message hold no secret or account data, including the login flow.
- `configure` writes: modes 0600 and 0700 at creation, temp file plus rename in the resolved directory, a symlinked file stays a symlink, secrets never taken from argv, no echo, no prompt without a terminal.
- Destructive commands fail without `--yes` before any request; read-only profiles refuse every write before any request, and a flag cannot undo a profile or env setting.
- Exit codes match the design table for every error class, including `ErrNoCredentials`, `ErrCredentialsFile`, `LoginError`, 401 after retry, `NotFound`, `ErrInvalidInput`, and cancellation.
- The JSON encoder uses Go field names and never leaks unexported fields; `--query` errors are usage errors.

### Task 1: SDK error codes, `LoginError`, debug logging

**Files:** `internal/core/errors.go`, `internal/core/client.go`, `internal/core/auth.go`, `internal/transport/transport.go`, `internal/iamuser/login.go`, their tests, `vngcloud.go`, `docs/wiki/Authentication.md`, `docs/wiki/Configuration.md`.

- `APIError.Code`: when the API gives no code, fill it from the status: 400 `BadRequest`, 401 `Unauthorized`, 403 `Forbidden`, 404 `NotFound`, 409 `Conflict`, 429 `Throttled`, 5xx `ServerError`, other 4xx `ClientError`. An API code (including billing's numeric envelope codes and the billing `NotFound` mapping) wins. Transport errors with no status keep an empty code.
- `*LoginError{Reason string; CaptchaSuspected bool; Err error}` wraps `ErrAuth` (`errors.Is(err, vngcloud.ErrAuth)` stays true). Every `iamuser.Login` failure maps to it with a fixed reason text (for example "sign-in form re-displayed", "2FA code rejected", "token exchange failed"), never a credential, email, code, or response body. Root re-exports `LoginError`.
- `Config.ProfileSetting(key string) string` returns a config-file key from the profile `LoadConfig` resolved (empty when absent or when the Config came from `NewConfig`), so the CLI reads `output` and `read_only` without its own resolver.
- `WithLogger(*slog.Logger)`: the transport logs one Debug record per HTTP attempt with `method`, `path` (no query), `status` (0 on a transport error), and `duration`; IAM login logs `login started` and `login finished` with `ok` true or false. Nothing else is logged. A nil logger logs nothing.
- [ ] Tests first: status codes for each class; API code wins; `LoginError` for each login failure path with a `secret-XYZ` password and `user@example.invalid` email absent from `err.Error()`; a captured slog handler sees exactly the fields above, and a request with `?token=abc` in its URL and a secret header logs neither. Then implement. Checks. Commit `feat(errors): add status-derived error codes, LoginError, and debug request logs`.

### Task 2: CLI root, global flags, config, errors, exit codes, `version`, read-only

**Files:** Create `cmd/vngcloud/main.go`, `internal/cli/root.go`, `internal/cli/config.go`, `internal/cli/errors.go`, `internal/cli/version.go`, and tests.

- `main` calls `os.Exit(cli.Main(ctx, os.Args[1:], os.Stdin, os.Stdout, os.Stderr))` with a context cancelled on SIGINT and SIGTERM. `cli.Main` builds a fresh root command per call so tests run it in-process.
- Global flags: `--profile`, `--region`, `--project-id`, `--output`, `--query`, `--yes`, `--debug`, `--read-only`. Config: `vngcloud.LoadConfig` with `WithProfile` only when `--profile` is set, `WithRegion`/`WithProjectID` only when set, `WithTokenCache(<home>/.vngcloud/cache)`, and `WithLogger` (stderr text handler, Debug level) only with `--debug`. `--output` defaults to `cfg.ProfileSetting("output")`, else `json`.
- Read-only: on when `--read-only`, `VNGCLOUD_READ_ONLY`, or the profile's `read_only` is `1` or `true`; `0`, `false`, or empty is off; any other value is a config error (exit 2). The flag and env are checked before `LoadConfig`, the profile key right after it. Each source can only turn it on. Error JSON classes for non-API errors follow `docs/design/cli.md`.
- Errors to stderr as `{"error":{"code":...,"message":...,"status":...,"operation":...}}` (omit empty fields). Exit codes: 0 success; 3 for `ErrNoCredentials`, `ErrCredentialsFile`, `*LoginError`, or `ErrAuth`; 4 for `IsNotFound`; 2 for usage errors, `ErrInvalidInput`, `ErrInvalidConfig`, `ErrProjectAmbiguous`, missing `--yes`, read-only refusal, and `--query` compile errors; 1 for everything else, including cancellation. Check the credential sentinels before `ErrInvalidConfig`, because they wrap it.
- `vngcloud version` prints the module version from `debug.ReadBuildInfo` (or `(devel)`), Go version, and OS/arch.
- [ ] Tests first: each exit code from a stub command; error JSON shape; `--debug` wiring (a fake API; stderr holds method, path, status, and no secret markers); read-only precedence (profile on plus no flag, env on, flag on); `version` output. Checks. Commit `feat(cli): add the vngcloud command root, errors, and exit codes`.

### Task 3: Operation tables and flags

**Files:** Create `internal/cli/op.go`, `internal/cli/flags.go`, `internal/cli/input.go`, and tests.

- `cli.Op`; `cli.Read(name string, method func(*C, context.Context, *In) (*Out, error), opts ...OpOption) Op`; `cli.Write(...)` with `cli.Destructive()`; `cli.Flag(field, flag string) OpOption`. `cli.Service(name string, newClient func(vngcloud.Config) *C, ops ...Op)` registers a service command.
- Flags by reflection over the Input struct: exported fields only; names kebab-case (`ServerID` to `--server-id`, `VPCID` to `--vpcid`); types string, int, int64, bool, `[]string`, `time.Time` (RFC 3339), and pointers to string, int, int64, bool (set only when the flag is `Changed`). Other field types are reachable only through `--cli-input-json '<json>'` or `--cli-input-json file://path` (Go field names as keys; unknown keys are a usage error). Flags apply after the JSON. Required fields are left to the SDK, whose `ErrInvalidInput` maps to exit 2.
- `Write`: `--debug` logs `write started` and `write finished`; with `Destructive`, the command fails before building a client unless `--yes`; read-only refuses every `Write` before building a client.
- [ ] Tests first against a fake service and an `httptest` server: flag names and types; pointer flags absent unless given (`--enabled=false` sends false); JSON then flag merge; `file://` input; unknown JSON key; destructive guard with and without `--yes`; read-only refusal for a write and pass for a read; the fake server sees zero requests for every refusal. Checks. Commit `feat(cli): build operation commands from SDK Input structs`.

### Task 4: Output

**Files:** Create `internal/cli/output.go`, `internal/cli/encode.go`, `internal/cli/render.go`, tests, and `internal/cli/testdata/golden/`.

- Encoder: walks the Output value by reflection; structs become objects keyed by Go field names in declaration order, embedded structs flatten like `encoding/json`, JSON tags are ignored, unexported fields are skipped, maps keep their keys, nil pointers and nil slices become `null` and `[]`, `time.Time` becomes RFC 3339, `json.RawMessage` passes through.
- `--query` compiles once with go-jmespath; a compile error is exit 2; it runs on the encoded JSON value.
- `json` prints indented JSON. `text` prints tab-separated values: a list of objects gives one row per item with keys sorted; a list of scalars one per line; an object one `key<TAB>value` line per key. `table` draws a bordered grid with sorted-key headers for a list of objects and a two-column grid for an object.
- [ ] Golden tests for each format on a list, a get, a nested object, a map-backed model, nulls, and a `--query` projection; `-update` flag regenerates goldens. Checks. Commit `feat(cli): add json, text, and table output with --query`.

### Task 5: Service tables

**Files:** Create `internal/cli/services/billing.go`, `pricing.go`, `compute.go`, `network.go`, `dns.go` (or one file per service under `internal/cli/`), and tests.

- Every operation of those five SDK packages gets an entry, named by kebab-casing the method. Billing kinds and `--yes` follow `docs/design/billing.md` "CLI": `delete-budget` and `delete-budget-threshold` are `Write` with `Destructive`; other creates and updates are `Write`; `pricing get-quote` is `Read`.
- Flag overrides where kebab-casing reads badly (`VPCID` to `--vpc-id`, `UUID` suffixes to `-uuid`), applied consistently; list them in the generated docs.
- [ ] Tests: each service command's help lists its operations; one read per service against a fixture-backed `httptest` server prints golden JSON; `billing delete-budget` without `--yes` exits 2 with zero requests; `billing update-budget --budget-uuid b --status PAUSED` sends only `status`. Checks. Commit `feat(cli): add billing, pricing, compute, network, and dns commands`.

### Task 6: `configure`

**Files:** Create `internal/cli/configure.go`, `internal/cli/configfile.go`, and tests.

- `configure` and `configure set` exit 2 while `--read-only` or `VNGCLOUD_READ_ONLY` is on; `get` and `list` still work.
- `vngcloud configure [--profile p]`: requires a terminal on stdin (`term.IsTerminal`), else exit 2 with a message naming `configure set`. Prompts for region, root email, username, password (no echo), and TOTP secret (no echo, optional); shows existing non-secret values as defaults and secrets only as `****`.
- `configure set <key> <value>`, `configure set <key> -` (value from stdin, trimmed of one trailing newline), `configure get <key>`, `configure list`. Keys and files per the design table plus `read_only` (config). `password` and `totp_secret` accept only `-`; a literal value is exit 2 and is never written. `get` and `list` mask `password` and `totp_secret`.
- Writes: resolve the target with `filepath.EvalSymlinks` when it exists; create `~/.vngcloud` 0700 if missing; write through `os.CreateTemp` in the resolved file's directory, 0600, `Sync`, `Close`, `Rename`; preserve comments and other sections by editing the parsed lines, not regenerating the file; `default` vs `[profile name]` sections as the SDK reads them.
- [ ] Tests first: `set` then SDK `LoadConfig` reads the value back; symlinked credentials file stays a symlink and the target changes; modes 0600 and 0700; a literal password is refused and the file is unchanged; `-` reads stdin; no terminal means exit 2 with zero writes; `get`/`list` mask secrets and never print markers. Checks. Commit `feat(cli): add configure for profiles and credentials`.

### Task 7: Generated docs

**Files (cli):** Create `internal/cli/gendocs.go` and test; generated `docs/wiki/CLI.md` (index, global flags, exit codes, read-only) and `docs/wiki/CLI-<Service>.md` per service; update `docs/wiki/_Sidebar.md` and `docs/wiki/Home.md`. **Files (manager):** `Makefile` target `gen-docs` (`go run ./cmd/vngcloud gen-docs docs/wiki`), CI step `make gen-docs && git diff --exit-code -- docs/wiki`.

- Hidden `vngcloud gen-docs <dir>` writes deterministic Markdown (sorted, no timestamps) from the operation tables: each operation's flags, types, required marks, kind (read, write, destructive), and one example. Pages wrap at 80 columns except tables.
- [ ] Test that two runs produce identical bytes and that every registered operation appears. Checks plus `make wiki-preview`. Commit `docs(cli): generate CLI reference pages`.
