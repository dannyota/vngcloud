# IAM users implementation plan

The base create/delete/read SDK, CLI, and wiki and the reset slice are implemented. Google MFA transition evidence and the remaining design and plan passed independent review under [administration decision 8](../design/iam-users-admin.md#owner-decisions). The Google SDK, CLI, wiki, and live helper are implemented and independently reviewed. Authorized live verification passed the full Google cycle, attributable deletion, and quota restoration. Release readiness is complete; landing and tags follow the exact-head validation procedure below. Each administration slice ships with SDK/CLI/wiki and reviewed helpers together after its own evidence gates and independent reviews. This plan authorizes no live call, credential access, cleanup, implementation of an unresolved schema, or publication bypass.

## Constraints

- Authorities: [design](../design/iam-users.md), [API and checks](../design/iam-users-api.md), [administration design](../design/iam-users-admin.md), [administration API and checks](../design/iam-users-admin-api.md), [IAM guards](../design/iam-writes.md#guards), [CLI](../design/cli.md), [accepted ADRs](../adr/README.md), [routing](../../AGENTS.md#ai-agent-definitions-and-routing), [workflow](../../instructions/workflow.md), [testing](../../instructions/testing.md), [security](../../instructions/security.md), [live data](../../instructions/live-data.md), [Go](../../instructions/go.md), [documentation](../../instructions/documentation.md), and [release](../../instructions/release.md). Stop on overlapping ownership, conflicting authority, or a missing contract.
- The manager owns decisions, briefs, credential-free worktrees, evidence sanitation, verification, live runs, Git, PRs, release notes, tags, and publication. Workers never read `.env`, private example configs, or `examples/basic/output/`, change Git state, fetch dependencies, or make live/network calls. Use the CLAUDE.md sandbox settings. Workers are not alone and preserve others' changes.
- Code workers use `gpt-6.1-sol` medium through implementer. Failure investigation and fixes use `gpt-6.1-sol` xhigh through troubleshooter. Separate reviews and fix confirmation use `gpt-6.1-sol` xhigh through design_reviewer or code_reviewer. Dispatch explicitly names model and effort. A designer never implements the slice, and a reviewer neither fixes nor reviews its own source. At most three workers run across all slices, including nested workers.
- Run dependent work in order. The administration headings describe separate dispatchable slices, not a requirement to finish all SDK slices before any CLI/release work. Each worker owns only the exact paths in its brief; no simultaneous writers share paths. Shared registries and documentation belong to one named worker. The manager inspects edits and checks before dependent work; a worker report alone does not close a gate.
- Keep public service boundaries and standard-library-only SDK dependencies. Preserve User and ListUsersOutput. Name is optional, but adding it breaks unkeyed ListUsersInput literals; new body caps are also a behavior change. Record both limits rather than promise complete source compatibility.
- Keep passwords out of argv, logs, captures, public fixtures, test names, and golden values. Synthetic canaries may appear only in test inputs; inspect supported formatting paths and every reachable error node. No real account data enters worker worktrees or reports.
- Agent-only files use one line per paragraph or list item and stay at most 450 lines. Human prose wraps at 80 columns. No dates, em dashes, or plan, task, or review IDs in living docs, code, comments, or tests. Generated pages change through source notes.

## Common checks

Every implementation brief requires focused behavior tests, `make check`, `go vet -tags live ./...`, `go vet -tags livewrite ./...`, `go test -tags live -run '^$' ./livetest/`, `go test -tags livewrite -run '^$' ./livetest/`, `bash scripts/check-sdk-deps.sh`, `git diff --check`, and generated-doc freshness. Compile-only live checks make no API calls. Do not retry a flaky check into a pass; report missing tools or caches to the manager.

Generate documentation with `go run ./cmd/vngcloud gen-docs <scratchpad>/generated-wiki` in private scratch space and compare all generated pages with docs/wiki. Only the CLI/wiki owner copies its named generated page. Wiki changes also require `make wiki-preview` and local page-link and anchor inspection. The manager runs `make check` before every commit, including document-only commits.

Use `httptest`, injected private randomness, controlled contexts, synthetic values, temporary files, and request counters. New behavior gets a failing test before implementation. Consume sanitized raw fixtures through the SDK; never mistake decoded SDK output for raw evidence.

### Observed-status and empty-body transport prerequisite

- Steps: add `KeepObservedStatus bool` to `transport.Request`; when it is set and the response body read or close fails after a status was received, return a transport `*APIError` carrying that observed `StatusCode`, the sanitized network cause, and context identity, instead of status 0. Requests that leave it unset keep status 0, so no existing caller changes behavior; the IAM user create, reset, and MFA sends set it, so a caller can tell an accepted 2xx and a definite 4xx from an unknown send. Keep `NotSent` false, keep Retryable under the existing rules, keep redaction of sent credentials, and change nothing for overflow, dial, or pre-status failures.
- Steps: in `wrapTransportErr`, for an error from a request that set `KeepObservedStatus` (marked on the transport error, so every other error keeps its current chain), keep both the mapped sentinel (`ErrNotFound`, `ErrAuth`, `ErrPermission`, `ErrRateLimited`) and the sanitized transport cause reachable through `errors.Is` and `errors.As`, for example by wrapping both causes, so a 404 followed by a canceled body read still matches `context.Canceled`; preserve `StatusCode`, `Code`, `Message`, and `Retryable`, and change no case where the transport cause is nil.
- Steps: add `AllowEmptyBody bool` and a per-call `BodyWasEmpty *bool` to `transport.Request` under the [empty-body contract](../design/iam-users-api.md#bounds-and-strict-decoding): when `AllowEmptyBody` is set and a success status carries a zero-length body, `doJSONStatus` skips `ValidateStrict` and `json.Unmarshal`, leaves `out` untouched, and sets `*BodyWasEmpty = true`; every other body, including whitespace only, follows the existing strict and sanitized path, and the flag is reset to false at the start of each call. No existing request sets the option, so every guard read keeps rejecting an empty body.
- Steps: failing tests first: transport tests that an empty 201 with `AllowEmptyBody` decodes nothing and reports the flag, that `{}` decodes and leaves the flag false, that a whitespace-only, `null`, array, or malformed body under `Sensitive` returns the withheld decode error with the flag false, that an empty body without the option still fails, and that each shipped guard read rejects an empty body with no write sent; transport tests that a 201, 204, and 404 whose body read fails and whose close fails each keep their status in `errors.As`, carry no body text, keep a canceled context identity, and change no retry count; overflow behavior is unchanged; a `Sensitive` request withholds the cause text as before. Public-SDK tests through `httptest` and an `iam` read that a 404, 401, 403, and 429 followed by a canceled or failed body read match both the mapped sentinel and `context.Canceled` or the sanitized cause, that the CLI error mapping reports cancellation for such an error, and that every existing status-mapping test still passes.
- Checks: common checks, `go test -race ./internal/transport ./internal/core ./iam ./internal/cli`, and the independent adversarial review. The IAM user designs assume this flag: the create, reset, and MFA sends set it, and their outcome tables classify a 2xx or 4xx with a body read or close failure by the kept status.
- Done: every existing service test still passes unchanged, and a request that sets `KeepObservedStatus` keeps its observed status through read and close failures.
