Contracts stay in those authorities; this plan owns order, assignments, open gates, and acceptance and grants no live-run, purchase, or cleanup authority.

## Ordered, independently landable slices

Implementation completion, landing, and feature tagging are separate gates; each code row includes its tests and docs and can land without enabling a dependent unverified contract. The quote-body probe is complete; fixture and pricing-safety acceptance remain separate from the feature tag.

|Order|Slice|Assignment|Dependency and acceptance|
|-|-|-|-|
|1|R1 public address reads|Complex implementer and complex reviewer|Free schema/synthetic coverage and bounded reads; can land and tag first and alone without a live write|
|2|Pricing safety and quote fixtures|Complex implementer/reviewer; manager for raw provenance|Body probe complete; preserve 1 MiB bound, verify capture safety, and decode supplied sanitized raw fixtures before R2 builder acceptance|
|3|R2 public create, total quote, exposure guard|Complex implementer and complex reviewer|R1 and probe contract plus verified group schema; implement reviewed contracts, then close public-create/charge/settlement/cleanup evidence in L4 before tag|
|4|R3 list/get and existing-IP attach/detach/delete|Complex implementer and complex reviewer|R2 quote/schema foundation and raw WAN gates; management evidence and L4 before tag; existing-IP reuse only|
|5|L4 and release evidence|Manager; complex implementer/reviewer for live-test code|One server and one IP under 500,000 VND gross quote cap, fresh run approval, verified cleanup; tags only for covered R2/R3 portions after passing|

R1 and remaining pricing safety/fixture work may run in parallel in separate worktrees because their implementation paths differ; the manager serializes captures against live writers and integrates their shared docs separately. R2 follows R1 and the quote probe; R3 follows the R2 foundation and its raw evidence, so do not run whole R2 and R3 slices concurrently. R1/R2 share `compute/compute.go`, `compute/waits.go`, server tests, CLI goldens, and compute wiki/generated pages; R1/R3 share `network/network.go`, network tests, and network wiki/generated pages. The probe/R2 share `pricing/pricing.go` and pricing tests; R2/R3 share exposure helpers, errors, `internal/cli/gendocs_notes.go`, and `Services.md`, `Billing-and-Pricing.md`, and generated `CLI.md`. An R2-only L4 can supply R3 row evidence for later implementation and a separately approved R3-only run; combined mode requires R3's preimplementation raw gates already closed, never keeping paid resources alive while implementing missing schemas. The manager may divide disjoint SDK, CLI, or documentation work after prerequisites are accepted, with explicit non-overlapping briefs and serialized shared-file integration; worker count alone never establishes safe parallelism.
