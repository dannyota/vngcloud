# vMonitor check state and quotas implementation plan

Implement the accepted [domain design](../design/monitor-quotas.md) in independently gated slices. [API evidence and checks](../design/monitor-quotas-api.md) owns wire facts, fixtures, deterministic checks, and live prerequisites; [quota lifecycle](../design/monitor-quotas-lifecycle.md) owns delete, purge, and auto-renew. The design's [owner decisions](../design/monitor-quotas.md#owner-decisions) are decided; this plan grants no live-run authority.

## Execution and gates

- [ ] Obtain separate independent design/plan review before code; the owner decisions are recorded in the design. Do not count design improvement as independent review. Use the repository routing and three-worker total limit; designers never implement their slice and reviewers never fix or review their own work.
- [ ] Dispatch implementers on `gpt-6.1-sol` medium, troubleshooters on `gpt-6.1-sol` xhigh for failures, and separate design/code reviewers on `gpt-6.1-sol` xhigh for reviews and fix confirmation. Every brief states model, effort, exact owned paths, authorities, required checks, and forbidden actions.
- [ ] Give workers separate credential-free worktrees and disjoint ownership. Require `git status --short`, preservation of others' edits, no Git mutations, no secrets/private configs/captures, no live calls, and no unrelated network or edits outside the brief. The manager owns Git, integration, and live verification.
- [ ] Close evidence dependencies before issuing the affected implementation brief. The manager performs separately approved private probes without relying on the unimplemented SDK, sanitizes raw responses, and supplies operation/status provenance. Do not authorize guessed fixtures or inferred recovery code merely because release is later gated.
- [ ] Keep reads first; ship free Email next without waiting for SMS or paid writes. Free synthetic extension can proceed independently once its own gates and shared write mechanism are accepted. Each extension, SMS operation, and recovery path needs separate evidence and review. Paid packages ship with the order and renewals whenever `--max-price` covers the higher of quote and list price; quotes are pre-VAT, and no debit or tax evidence gates them. Auto-renew, then delete and purge, follow the renewals under the lifecycle sibling.
- [ ] Preserve the frozen-terms pricing contract for all writes: one immutable set of terms (kind, package, `monthPeriod` 1, and for renewals the frozen quota identity and expiry) mapped by one builder per write to its evidenced quote request and mutation body, as the design's mapping table states. No quote endpoint accepts a mutation body; never add quote-only fields to a mutation, drop fields to make a quote pass, or send a period other than 1. A write whose quote mapping lacks live evidence stays blocked.
- [ ] The manager records remaining monthly action allowance privately before each mutation probe and reserves a possible action for every attempt. Unknown budget blocks mutation; do not assume extensions, failures, deletion, or synthetic calls are exempt. Keep free quotas and never run an automatic cleanup purchase/delete cycle.
- [ ] Keep the SDK standard-library only and the CLI on public SDK calls. No dependency or generic CLI flag-type change is planned. Preserve existing log-project semantics; avoid an unrelated shared-helper refactor.

## Common write mechanism and Email order

- [ ] Build the common mechanism with the first evidence-cleared write, whether Email create or synthetic extension; it has no Email schema dependency. Implement only after single-send, price, wait, and reconciliation tests fail for the intended reason. - [ ] Test Once at every layer: no second mutation on 401, 429, failed dial, 5xx, disconnect, context cancellation, or redirects. Preserve errors.As status and errors.Is sentinels while withholding raw peer text and paymentUrl from errors and all outputs.
- [ ] Implement the context-aware per-Client lock through preparation/send/settlement and the unresolved-attempt block, including NoWait. Reconciliation reads may repeat; writes may not. Test delayed visibility, concurrent calls, cancellation while waiting for the lock, definite rejection, inconclusive read, a matching call receiving the confirmed prior result, and a changed-baseline renewal or a create after an unresolved renewal receiving ErrInvalidInput that names the prior attempt rather than a fulfilled result or a new send.
