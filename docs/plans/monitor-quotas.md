# vMonitor quota coverage implementation plan

Implement the accepted [quota design](../design/monitor-quotas.md), [coverage contracts](../design/monitor-quota-coverage.md), [API evidence and checks](../design/monitor-quotas-api.md), and [lifecycle rules](../design/monitor-quotas-lifecycle.md). The [unattended CI contract](../design/cli.md#unattended-ci) covers environment auth and installation. Contracts live there; this plan owns order, assignments, open gates, and acceptance. It grants no live-run authority.

## Baseline and gates

The code has check state/history, quota reads, Email/SMS packages and create/quote, notification auto-renew disable and active delete, and the synthetic auto-renew refusal. Preserve their public types and behavior. SMS usage remains refused. This baseline records code presence, not a new verification or review claim.

The owner directs implementation of synthetic recovery and renewal now. An in-window renewal no longer gates implementation; the manager performs the first run as the live success check. The response policy explicitly tolerates the missing live success bodies without treating a response as settlement. Email renewal is removed from this sequence under owner direction. Email and SMS renewal/recovery remain deferred, as do notification auto-renew enable, synthetic delete, and purge.

- [ ] Obtain independent design and plan review before implementation. Design authors never implement their slice; reviewers never fix or review their own work. Approval is not API evidence.
- [ ] Dispatch implementers on `gpt-6.1-sol` medium, failure investigation and fixes to troubleshooters on `gpt-6.1-sol` xhigh, and independent design/code review and fix confirmation on `gpt-6.1-sol` xhigh. Every dispatch names model, effort, exact ownership, authorities, forbidden actions, and required checks.
- [ ] Use separate credential-free worktrees and disjoint paths, with at most three workers total. Require `git status --short`, preservation of other edits, no Git mutations, no secrets/private captures or network outside checks, and no live calls. The manager owns integration, Git, and approved live verification.
- [ ] Supply the manager-reported raw ListSyntheticQuotaClasses.json (absent here), settings, and post-recovery quota fixtures with provenance before their dependent decode implementation. Preserve distinct v1/class package IDs and consistent class/quota/detail/quote IDs; never edit IDs to manufacture a join. Keep the manager's CLI projection as timing evidence only. Missing fixtures gate those decode checks, not permission to write defensive synthetic response handling. Never invent a live response fixture.
- [ ] Keep standard-library-only SDK boundaries and public SDK calls from the CLI. Add no dependencies, generic flag-type changes, public settings/trash operation, or notification-channel shorthand. Preserve log-project semantics and existing quota helpers unless a bounded brief names a necessary change.

## Ordered, independently landable slices

Each row includes SDK, CLI, tests, and user docs so it is useful on its own. Shared paths pass to the next worker only after manager acceptance. Do not parallelize these rows. A slice can land while later evidence gates remain open.

|Order|Slice|Dependency and result|
|-|-|-|
|1|Synthetic catalog and nullable limits|Raw class/settings/package/detail fixtures; list class options and v1 packages separately with source-specific price, capacity, periods, and eligibility; preserve old detail integers|
|2|Quota status summary|Existing quota/detail and notification package reads; compose selected rows with --kind, per-row errors, none handling, UTC time, renewal window, and safe command hints; use read fallbacks until writes land|
|3|Synthetic recovery|Existing lock/ledger/Once mechanism, recovery request/quote evidence, raw before/after quota fixtures; recover only the expected expired IN-TRASH free quota and confirm by read-back with structured outcomes on every return|
|4|Synthetic renewal and quote|Existing shared mechanism and live quote/early-409 fixtures; implement ACTIVE extension with expected expiry, price, and day guards, structured outcomes, and CI docs; first in-window run remains a manager live check|

Slices 3 and 4 do not authorize synthetic creation, paid orders, or any cleanup. A priced ACTIVE class alone does not verify a paid write. Preserve lifecycle support gates and all original alarm/history and notification regression checks.

Equal limits/names never join identities or copy prices/eligibility. No v2/packages fallback and no future paid write authorization.
- [ ] Add nullable channel limits without changing existing int fields. Test explicit zero versus null, legacy field compatibility, required-key failures, and Telegram unknown semantics. Document unkeyed literal/exact-output limits in the same slice.
- [ ] Implement GetQuotaStatus using existing reads, with one injected AsOf and exactly the selected rows: optional Kind filters synthetic/email/sms, empty selects three. Test source quota NotFound versus detail/list failure, all-none success, unknown packages/prices/status, UTC conversion, signed time left without duration overflow, and the exact renewal-window boundary. Assert a synthetic filter sends only quota/detail reads, with zero package/notification/classes/settings/usage/quote/trash/mutation calls. Its price/class come from detail, PackageName stays unknown, and Quota.PackageID remains the class-side ID even when v1 limits coincide. ## Recovery and renewal acceptance

- [ ] Use the parent and coverage contracts for Inputs, Outputs, immutable terms, request construction, guards, and errors. Copy caller inputs before I/O. Local invalid shapes, missing required fields, invalid finite budgets, and read-only refusal send zero requests. Eligibility or price refusals after reads send zero mutation requests.
- [ ] Recovery tests cover expected ID, expired IN-TRASH only, exact-now refusal, quota/detail package equality and Basic detail capacity, quote capacity rather than usage, and complete final reread including detail class/location/price. Renewal tests cover required RFC 3339 ExpectedEndTime, instant-equivalent offsets, stale baseline, MaxDaysLeft skip after eligibility, threshold overflow, ACTIVE future expiry only, and expiry crossing while quoting. Neither operation falls back to recovery/create/renew after 404 or other ineligibility.
- [ ] Check the exact quote and mutation bodies from one frozen term set: period 1, pay true, fixed redirect, quote-only resourceId/packageId/quantity kept out of mutation. Use quota.PackageID in the quote and read-back, never the v1 ID. Use identity-checked detail price as synthetic ListPrice, refuse missing prices, guard max(ListPrice, quote), keep ErrUnpriced, and refuse paid synthetic even with a larger MaxPrice. Prove zero package/class/settings calls for both writes and QuoteRenewSyntheticQuota; mismatch in quota/detail fails before quote. No catalog/quote retry loop may rebuild terms.
- [ ] Prove Once at the real transport boundary for each new operation: count requests/dials under 400/401/403/404/409/429, 500/502/503/504, dial failure, disconnect after reading the body, timeout, cancellation, and all redirects. Assert no auth resend and at most one mutation attempt. Retain HTTP/1 stale-connection and HTTP/2 REFUSED_STREAM/GOAWAY tests, replay controls, and idempotency-header stripping. A mocked SDK send counter alone is insufficient.
- [ ] Keep early 409 a visible Conflict APIError, safe operation/status, no record and no confirm reads; unrelated 409 text has the same classification. Test definite 4xx and proven-not-sent failure versus possible-send uncertainty, preserving errors.Is and errors.As without raw messages.
- [ ] Implement tolerant synthetic response handling separately from notification create. Test empty/null/missing optional fields, unknown keys, optional safe OrderID, payment URL echo versus external URL, wrong types, malformed/oversize JSON, and unexpected statuses. All body variants remain unconfirmed until read-back; never fabricate a live success schema from mocks.
- [ ] Confirm recovery/renewal only on the frozen ID/package, ACTIVE, and later EndTime. Test unchanged expiry, leaving trash alone, empty trash, replacement ID/package, delayed visibility, 404/CREATING, read error, cancellation, and the hard 120-second bound during slow reads. NoWait leaves a false confirmation and an open record; only a matching later read can fulfill it.
- [ ] Extend the existing quota lock and ledger across recovery, renewal, and auto-renew. Test repeated same-intent calls, changed baseline, changed operation, open-record expected-ID mismatch, lock cancellation, two callers, credential refresh during reconciliation, and unchanged reads never proving rejection. While a retained attempt is unresolved, a mismatched ExpectedQuotaID or ExpectedEndTime preserves its Sent, Stage unconfirmed, and NotSettled wrapping ErrQuotaChanged, with zero new mutations. After resolution, guard mismatch returns QuotaChanged; other changed intent returns ErrInvalidInput without sending. Test both retained yes and unknown, failed/inconclusive reconciliation, and errors.Is for both sentinels. Do not reset clients to bypass uncertainty.
- [ ] Register new writes as Write; enforce explicit MaxPrice presence including zero from flag/JSON and required identity/expiry guards, with existing precedence. Hide ignored quote flags. Test pre-network read-only refusal, all error exit codes, full output before every error, including pre-SDK validation/config/auth failures, NoWait exit 0 without a confirmation claim, and uncertainty precedence over auth/cancellation/404. Positive budgets retain the cost warning.
- [ ] Run all five attacker-model checks from the parent threat analysis. Retain existing create/lifecycle, safe output, capture suppression, credential/cache, redirect, and log-project regressions. No deletion, repurchase, or cleanup authority follows a test failure or unconfirmed write.

## Unattended CI acceptance

- [ ] Implement the coverage outcome table once, shared by recovery and renewal. Test every row's exact JSON fields, Sent/Stage, safe Error.Code/Status/Operation, confirmation boolean, error identity, stderr agreement, and exit. Initialize SDK Outputs before validation; only read-back confirms. Keep ErrQuotaChanged distinct from ErrInvalidInput and test stale expiry before MaxDaysLeft skip, recovery expected-ID mismatch, and final-term races.
- [ ] Preserve send evidence independently from settlement: product read/quote status never sets Sent yes; proven pre-SDK/transport no-send stays no; a mutation response sets yes even on a definite refusal; missing response with possible transmission is unknown. Guard mismatch cannot reset retained evidence to no or clear the account/kind hold; NotSettled wins until resolution. A changed intent cannot claim the prior operation. Reject --query before requests on these two writes.
- [ ] Drive recognized-command missing flags, malformed JSON, invalid output/consent/query, read-only, config/auth/cache failures, every SDK outcome, and rendering failure through the CLI boundary. Assert one complete stdout record when writable and one safe stderr error envelope; never print the result twice or claim no-send after a render failure. Retain existing command-output regressions.
- [ ] Run both actual CLI commands through their public SDK and real product HTTP transport with a positive retry count, using loopback servers and synthetic auth. Do not stub the operation or replace the product RoundTripper. For every outcome-table row assert exact mutation-route counts per invocation: zero for pre-send refusal, not-due, and reconciliation; one for confirmation, definite server refusal, NoWait, and response/read-back failure. Count a body-receiving disconnect as exactly one, a failed dial as zero server mutations and exactly one dial attempt; coordinate cancellation before send (zero) or after body receipt (one) deterministically. A separate SDK test plus a mocked CLI test does not satisfy this proof. Assert stdout Sent/Stage/Error, stderr class, and exit alongside the counts; count quotes separately from mutations. Keep normal retries enabled so Once is actually exercised.
- [ ] Before the consumer enables its scheduled job, retain a release evidence record for its exact pinned version: release commit SHA, exact test command, CI run URL proving that SHA, per-case request-count assertions, and machine-readable stdout/stderr refusal results with exits. Cover not-due, price refusal, stale guard, early 409, uncertain send, and confirmation for renewal, plus corresponding recovery cases. Missing, failing, or mismatched-release evidence blocks enablement; another release's results do not substitute. Keep synthetic fixtures and artifacts free of credentials and account data.
- [ ] Test no-profile environment auth with synthetic VNGCLOUD_CLIENT_ID, VNGCLOUD_CLIENT_SECRET, VNGCLOUD_REGION, and VNGCLOUD_PROJECT_ID in an isolated temporary home, empty stdin, and fake auth/product transports. Assert no prompt/browser or required input file, safe automatic cache permissions, and no credential/Basic/bearer canary in stdout, stderr, debug, errors, or partial outcomes. Retain service-account source-selection, capture-isolation, failure-canary, and refresh tests. Use loopback only and no actual credential. Separately test SDK loaded-profile refusal and invalid values with zero requests; CLI flag/environment refusal must precede config loading, while direct SDK calls do not consult VNGCLOUD_READ_ONLY.
- [ ] Add the short CI wiki section with the four variables, pinned checksum-verified go install, exact outcome/exit table, and fresh get-synthetic-quota expiry example from the CLI contract. Include --max-days-left 7, --max-price 0, synthetic-only pre/post status, no --no-wait, serialization, durable pending marker, and read-only reconciliation after uncertain or missing output. Use the actual CLI JSON casing in the example. Release binaries/attestations and a repository Actions workflow are not this slice.
