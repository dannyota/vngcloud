# vStorage object transfers implementation plan

Build the accepted native SDK and file-only CLI transfers as one SDK, CLI, and wiki release.

For workers: follow the project's brief, ownership, worktree, routing, and review rules. Use test-first development within each task. The manager dispatches workers; workers never change Git state.

**Goal:** Upload and download arbitrary binary bytes with explicit S3 credentials and region, bounded streaming, protected replacement, and safe local publication.

**Architecture:** Add a separate standard-library `storage.ObjectClient` with its own HTTP transport and native Signature Version 4 signer. Handwritten object commands call that public SDK and reuse shared CLI policy, rendering, redaction, and error rules without entering management configuration or transport.

**Tech stack:** The repository-pinned Go toolchain, standard-library SDK, existing Cobra CLI, Linux/macOS safe file operations, deterministic synthetic tests and loopback HTTPS.

**Authorities:** [Object design](../design/storage-objects.md), [wire specification](../design/storage-objects-api.md), [storage](../design/storage.md), [CLI](../design/storage-cli.md), [settings evidence](../design/storage-settings.md), [keys](../design/storage-keys.md), [accepted ADRs](../adr/README.md), and [workflow](../../instructions/workflow.md).

## Review focus

1. A reused connection can cause hidden replay of zero-byte PUT. Task 2 must count server requests on dropped/stale connections and prevent transport replay rather than relying only on `GetBody == nil`.
2. GET headers do not prove a download completed. Task 2 checks clean EOF, limits, context errors, and deadline lifetime; Task 3 publishes only after completed copy, sync, and close.
3. Credential reflection can leak through success metadata, formatting, or local metadata. Tasks 1, 2, and 4 discard changed optional server fields and filter local display fields before rendering/querying.
4. A FIFO or symlink swap can defeat a preflight path check. Task 3 validates opened handles, avoids blocking credential opens, and publishes without a check-then-rename default.
5. A successful transfer followed by query, stdout, or publication-cleanup failure must not imply the transfer failed. Tasks 3 and 4 preserve published files and report completion without retry.
