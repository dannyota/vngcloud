# vStorage object operations implementation plan

Ship bounded object reads, unconditional current-name deletion, and native replacement copy as three complete SDK, CLI, help, and wiki releases, in that order.

For workers: use test-first development and the project's brief, ownership, worktree, routing, and review rules. The manager preserves the owner's parallel-agent execution choice and dispatches workers; workers never change Git state.

**Goal:** Extend `storage.ObjectClient` with one-page `ListObjects`, metadata-only `HeadObject`, standalone `DeleteObject`, and native `CopyObject` with explicit replacement consent.

**Architecture:** Reuse the isolated native S3 client and extend its private request signing, bounded XML, and filtered metadata helpers. Handwritten object commands call the public SDK and reuse safe credential loading, profile policy, rendering, and error classification without management authentication or transport.

**Tech stack:** Repository-pinned Go, standard-library SDK, existing Cobra CLI, synthetic raw fixtures, injected clocks, and loopback HTTP/TLS tests. Add no dependency.

**Authorities:** [Approved operations design](../design/storage-object-operations.md), [protocol and evidence](../design/storage-object-operations-api.md), [checks](../design/storage-object-operations-checks.md), accepted [transfer design](../design/storage-objects.md) and [protocol](../design/storage-objects-api.md), [transfer plan](storage-objects.md), [accepted ADRs](../adr/README.md), and [workflow](../../instructions/workflow.md). The owner's approval covers the written operations contract; independent plan review is the remaining code-start gate.

## Review focus

1. Query encoding and signed bytes can disagree on literal plus, percent, slashes, spaces, Unicode, and token delimiters. Task 1 pins published signatures and actual RequestURI; Task 2 checks opaque continuation tokens and literal key decoding.
2. Hostile XML can exceed depth/body/entry budgets or disguise known fields through namespaces, duplicates, nested scalars, or multiple roots. Tasks 1 and 2 and the copy plan verify complete bounded documents and nil failure Outputs.
3. Whole-field credential filtering can fail after percent/XML decoding, metadata lowercasing, or time normalization. Tasks 1 through 3 and the copy plan test required-field refusal and optional-field omission across direct SDK access, formatting, JSON, and CLI queries.
4. Bodyless DELETE/PUT can replay or report an ambiguous outcome as success. The delete and copy plans count real requests, distinguish pre-dispatch failures from unconfirmed outcomes, and prohibit verification, rollback, and retry.
5. CLI policy, consent, or output failure can load credentials prematurely or trigger another mutation. Task 4 and the delete/copy CLI tasks prove refusal ordering, error precedence, one dispatch, escaped metadata, and completed-operation output errors.

## Task 1: Shared request, XML, and metadata foundation

**Produced private interfaces:** `(*ObjectClient).objectBucketURL(bucket string) (*url.URL, error)`; `objectEncodeQuery(values url.Values) string`; existing `signObjectRequest(*http.Request, string, time.Time)` signs the exact encoded `RawQuery`; `newObjectXMLDecoder(r io.Reader, maxBytes int64, roots ...string) *objectXMLDecoder`; `(*objectXMLDecoder).Token() (xml.Token, error)`; `(*ObjectClient).objectScalarHeader(h http.Header, name string, maxBytes int) string`; `(*ObjectClient).objectTime(value string, maxBytes int, layout string) *time.Time`; `(*ObjectClient).objectUserMetadata(h http.Header) map[string]string`. These helpers are private, receive no public arbitrary-header/query surface, and never retain raw transport/parser errors or remote text in errors.

`objectXMLDecoder` is a bounded token wrapper for success parsers, not a decoded response model. It enforces body cap plus one probe, depth 16, one complete permitted root with absent/S3 namespace, initial declaration only, comments/whitespace, no directives/entities/external resolution, and clean EOF. Operation parsers own recognized-field uniqueness, scalar-only checks, field requirements, and filtering. Copy permits either CopyObjectResult or Error root but determines success only after full decoding.

Share exactly one query representation between RequestURI and canonical signing; never use form-style `+` spaces. Keep published GET/PUT vectors unchanged and add the published AWS bucket-list query vector with exact canonical hash/signature and UTC day rollover. A test-local independent signer supplements the vectors.
- [x] Write `TestObjectXMLBounds`: synthetic exact/over-cap bodies, depth 16/17, duplicate/wrong roots, namespaces and qualified lookalikes, unknown bounded subtrees, nested scalars, directives, external entities, processing instructions, invalid UTF-8, trailing content, and canceled reads.
