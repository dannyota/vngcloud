# v0.3.0 Service Tables

Operation tables and renames for Tasks 3 to 9 of [the v0.3.0 plan](2026-09-25-v0.3.0-service-packages.md). Read that plan's Global Constraints and Task 2 first; each task here repeats Task 2's steps. "L[T]" means `core.List[T]`; "P[T]" means `core.PagedList[T]`; "(r)" marks `vngcloud:"required"`.

## Task 3: `portal` (from `internal/portal`)

Renames: `PortalUserInfo`→`UserInfo`, `PortalZone`→`Zone`, `PortalQuota`→`Quota`, `PortalTagQuota`→`TagQuota`.

| Operation | Input | Output |
|-|-|-|
| `GetUserInfo` | none | `{UserInfo UserInfo}` |

## Task 9: `globalloadbalancer` (from `internal/glb`)

Renames: `GLBPackage`→`Package`, `GLBVLBPackage`→`RegionalPackage`, `GLBRegion`→`Region`, `GlobalLoadBalancer`→`LoadBalancer`, `GlobalLoadBalancerVIP`→`VIP`, `GlobalLoadBalancerDomain`→`Domain`, `GlobalPool`→`Pool`, `GlobalPoolHealthMonitor`→`PoolHealthMonitor`, `GlobalPoolMember`→`PoolMember`, `GlobalPoolMemberDetail`→`PoolMemberDetail`, `GlobalListener`→`Listener`, `GlobalLoadBalancerUsageHistory`→`UsageHistory`. The old `List...Result` structs had JSON tags because they decoded responses: keep them as unexported response types and map into the tagless outputs.

| Operation | Input | Output |
|-|-|-|
| `ListPackages`, `ListRegions` | none | L[Package], L[Region] |
| `ListLoadBalancers` | `Name`, `Offset`, `Limit` | `ListLoadBalancersOutput{Items []LoadBalancer; Offset, Limit, Total int}` |
