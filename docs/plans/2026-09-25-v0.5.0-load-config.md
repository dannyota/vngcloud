# v0.5.0 LoadConfig, Profiles, and Token Cache Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Tasks run in order; one final review after the last code task, adversarial because this release handles credentials. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add `vngcloud.LoadConfig`, which resolves a `Config` from options, `VNGCLOUD_*` environment variables, and AWS-style profile files; a pluggable `CredentialsProvider`; an opt-in on-disk token cache shared safely across processes; and fix the 401 retry so it logs in again instead of re-sending the rejected token.

**Architecture:** `internal/ini` parses the two files. `internal/core` gains the credentials provider interface, `Invalidate` on the token path, `LoadConfig`, and new options. `internal/tokencache` stores one token per credential set under a lock file. Root `vngcloud` re-exports the new names. No service package changes.

**Tech Stack:** Go 1.27.1, standard library only (`syscall.Flock` on Unix), golangci-lint 2.13.2.

**Spec (approved):** `docs/design/sdk-and-cli.md` sections "Root package", "Shared session", "Configuration and credentials" (Files, Precedence, File safety, Token cache), and the `v0.5.0` release row. The CLI's `configure` command and its file writes belong to the CLI release, not this one. `*LoginError` and the status-to-code table stay with the CLI release.

## Decisions this plan makes

- Cross-process locking uses `syscall.Flock` on Unix (Linux, macOS, BSD) behind a `//go:build unix` file. On other systems (Windows) the cache uses an in-process mutex only, and the wiki says two processes on Windows may each log in. The SDK stays standard-library only, and `syscall` has no portable file lock.
- Profile files ignore unknown keys (the CLI's `output`, future keys), as the AWS CLI does. A malformed line is still an error naming the file and line.
- `LoadConfig(ctx, opts...)` keeps its `ctx` for later sources; this release does not use it for I/O.
- The file mode check runs when `runtime.GOOS != "windows"`.

## Global Constraints

- Branch `v0.5.0` from `master`. The brief may allow the worker to make one signed commit per task; commits are signed by repo config, and nobody disables signing.

## Review Focus (adversarial)

- Precedence: options over env over profile; credentials resolve as one set from the first source that sets any credential; an explicit profile's credentials beat env credentials; `VNGCLOUD_PROFILE` is not explicit.
- A credentials file readable by group or others is refused before any value is used; the error names the file and `chmod 600` and holds no value.
- Token cache: dir 0700, files 0600, created with those modes (not chmod after); hash inputs length-prefixed; static tokens never cached; a malformed or unreadable cache file is a miss, never an error that blocks login; writes via temp file and rename in the same dir; the lock is held across read, login, and write.
- 401: the rejected token is dropped from memory and disk only when it is still the cached token, so parallel 401s cause one login, not several inside one TOTP window.
- No secret in any error, log line, or `--debug`-style capture.

### Task 1: `internal/ini` parser

**Files:** Create `internal/ini/ini.go`, `internal/ini/ini_test.go`.

**Interfaces:** `ini.Parse(name string, r io.Reader) (File, error)`; `type File map[string]map[string]string` (section name to key to value); `(File) Section(name string) (map[string]string, bool)`.

Rules: `[section]` headers (trim spaces inside brackets); `key = value` lines (trim both sides; keys lowercase; value keeps inner spaces; no quote handling); blank lines skipped; full-line comments start with `#` or `;` after optional spaces; a key before any section, a line without `=`, an empty key, or an unclosed `[` is an error `"<name>:<line>: <reason>"` that never includes the line's value. A repeated key keeps the last value. A repeated section merges.

### Task 2: `CredentialsProvider`, `Invalidate`, and the 401 fix

**Files:** Modify `internal/transport/transport.go`, `internal/transport/transport_test.go`, `internal/core/auth.go`, `internal/core/client.go`, `internal/core/client_options.go`, `internal/core/config_test.go` (or a new `internal/core/credentials_test.go`), `vngcloud.go`, `vngcloud_test.go`.

**Interfaces:**
- `transport.TokenSource` gains `Invalidate(accessToken string)`.
- `core.CredentialsProvider` interface: `Token(ctx context.Context) (Token, error)` and `Invalidate(accessToken string)`; `core.Token{AccessToken string; ExpiresAt time.Time}` (alias of `transport.Token` is fine).
- `core.WithCredentialsProvider(p CredentialsProvider) Option`. Exactly one of IAM user, static token, or provider may be set; more than one is `ErrInvalidConfig`.
- Root re-exports `CredentialsProvider`, `Token`, `WithCredentialsProvider`.

Behavior:
- On a 401, the transport calls `tokenSource.Invalidate(rejected)` with the token it sent, clears its own copy, fetches a new token, and retries once (as today, for every method).
- `IAMUserAuth` (`auth.go`) clears its cached token only when `cachedToken == rejected`. A second 401 carrying the same old token after another goroutine already logged in is a no-op, so parallel 401s cause one login.
- Static token `Invalidate` is a no-op; a second 401 surfaces as `ErrAuth`.

### Task 3: `internal/tokencache` and `WithTokenCache`

**Files:** Create `internal/tokencache/cache.go`, `internal/tokencache/lock_unix.go` (`//go:build unix`), `internal/tokencache/lock_other.go` (`//go:build !unix`), `internal/tokencache/cache_test.go`. Modify `internal/core/auth.go`, `internal/core/client_options.go`, `internal/core/client.go`, `vngcloud.go`.

**Interfaces:**
- `tokencache.New(dir string, now func() time.Time) *Cache`.
- `(*Cache) Do(ctx context.Context, key Key, login func(ctx context.Context) (Token, error)) (Token, error)`: takes the lock for `key`, returns the cached token when it has more than 30 seconds left, else calls `login`, writes the result, and returns it.
- `(*Cache) Invalidate(key Key, accessToken string)`: under the lock, deletes the file when it holds `accessToken`.
- `tokencache.Key{Profile, RootEmail, Username, SigninURL, TokenURL string}`; `(Key) Hash() string` is SHA-256 hex over each field written as `<decimal length>:<value>` in that order.
- `core.WithTokenCache(dir string) Option`; `core.WithProfile(name string) Option` (the profile name feeds the key; `LoadConfig` also uses it in Task 4). Root re-exports both.

Rules:
- `MkdirAll(dir, 0o700)`; if the dir exists with group or other bits set, return an error (Unix only) naming the dir, not a value.
- Token file `<dir>/<hash>.json` holds `{"accessToken":"...","expiresAt":"RFC3339"}`. Write to `os.CreateTemp(dir, ".tok-*")` created 0600, `Sync`, `Close`, then `os.Rename` onto the target.
- Lock file `<dir>/<hash>.lock` opened `O_CREATE|O_RDWR`, 0600, held with `syscall.Flock(fd, LOCK_EX)` for the whole read, login, and write. `lock_other.go` uses a package-level mutex per key and a doc comment saying cross-process locking is Unix-only.
- A missing, unreadable, malformed, or expired file is a miss. A file with 0 time left or less than 30 seconds is a miss.
- Only IAM User credentials use the cache. Static tokens and custom providers never touch disk. With no `WithTokenCache`, nothing is written.
- The IAM token path consults memory first, then the cache, then logs in; `Invalidate` clears memory and calls `Cache.Invalidate`.

- [ ] **Step 1: Failing tests** (fake clock; `t.TempDir()`):
  - Reuse: second `Do` within expiry does not call `login`.
  - Expiry: advancing the clock past `expiresAt - 30s` calls `login` again.
  - Key change: a different username, profile, sign-in URL, or token URL misses.
  - Hash: length prefixing distinguishes `{"ab","c"}` from `{"a","bc"}`.
  - Malformed, empty, and unreadable (mode 0000) files are misses and get overwritten.
  - Modes: dir 0700 and file 0600 on Unix; a pre-existing 0755 dir is an error without any token in the message.
  - Concurrency: two `Cache` instances on one dir (separate file descriptors) and 8 goroutines each call `Do`; `login` runs exactly once. Run under `-race`. Skip on non-Unix with a reason.
  - Invalidate: removes the file only when it holds the given token.
  - Core: a Config with `WithTokenCache` and an IAM user writes one file after the first call, and a second Config with the same credentials and dir makes no login request. A static-token Config with `WithTokenCache` writes nothing.

### Task 4: `LoadConfig`, env vars, profiles, file safety

**Files:** Create `internal/core/load.go`, `internal/core/load_test.go`. Modify `internal/core/client_options.go`, `vngcloud.go`, `vngcloud_test.go`.

**Interfaces:** `core.LoadConfig(ctx context.Context, opts ...Option) (Config, error)`; options `WithProfile(name)` (from Task 3), `WithConfigFile(path)`, `WithSharedCredentialsFile(path)`. Root re-exports `LoadConfig`, `WithConfigFile`, `WithSharedCredentialsFile`.

Resolution, in this order:
1. Apply `opts` to a settings value and record which fields they set.
2. Profile name: `WithProfile` (explicit) else `VNGCLOUD_PROFILE` else `default`.
3. Paths: option, else `VNGCLOUD_CONFIG_FILE` / `VNGCLOUD_SHARED_CREDENTIALS_FILE`, else `~/.vngcloud/config` and `~/.vngcloud/credentials` via `os.UserHomeDir`. A missing file is not an error. When the home dir is unknown and no path is given, skip the files.
4. Config section: `default` for the default profile, `profile <name>` otherwise. Credentials section: the bare name. Keys: config `region`, `project_id`; credentials `root_email`, `username`, `password`, `totp_secret`, `access_token`. Unknown keys are ignored. A named non-default profile that exists in neither file is `ErrInvalidConfig` naming the profile.
5. Credentials file safety: open it, `f.Stat()` on the open file, and on non-Windows refuse `mode&0o077 != 0` with `ErrInvalidConfig` naming the path and `chmod 600`, before parsing.
6. Region and project ID: option, else env (`VNGCLOUD_REGION`, `VNGCLOUD_PROJECT_ID`), else profile. Missing region after all sources is `ErrInvalidConfig`.
7. Credentials as one set from the first source that sets any credential value: options (IAM user, static token, or provider), then env (`VNGCLOUD_ACCESS_TOKEN`, `VNGCLOUD_ROOT_EMAIL`, `VNGCLOUD_USERNAME`, `VNGCLOUD_PASSWORD`, `VNGCLOUD_TOTP_SECRET`), then the profile. When the profile is explicit (`WithProfile`), the profile comes before env. Within one source, an access token wins over IAM User values. A TOTP secret becomes `&SecretTOTP{Secret: ...}`.
8. Build with `NewConfig` from the resolved values plus every non-credential option the caller passed.
