# v0.5.0 LoadConfig, Profiles, and Token Cache Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Tasks run in order; one final review after the last code task, adversarial because this release handles credentials. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add `vngcloud.LoadConfig`, which resolves a `Config` from options, `VNGCLOUD_*` environment variables, and AWS-style profile files; a pluggable `CredentialsProvider`; an opt-in on-disk token cache shared safely across processes; and fix the 401 retry so it logs in again, once, instead of re-sending the rejected token.

**Architecture:** `internal/ini` parses the two files. `internal/core` gains the credentials provider interface, compare-and-clear invalidation, `LoadConfig`, and new options. `internal/tokencache` stores one token per credential set under a lock file. Root `vngcloud` re-exports the new names. No service package changes.

**Tech Stack:** Go 1.27.1, standard library only (`syscall.Flock` on Linux, macOS, and BSD; `syscall.CreateFile` with share mode 0 on Windows), golangci-lint 2.13.2.

**Spec (approved, amended for safety):** `docs/design/sdk-and-cli.md` sections "Root package", "Shared session", "Configuration and credentials" (Files, Precedence, File safety, Token cache), and the `v0.5.0` release row. Design wins over this plan. The CLI's `configure` command, `*LoginError`, and the status-to-code table belong to the CLI release.

## Review Focus (adversarial)

- Precedence and credential sets, including the explicit-profile rule: with `WithProfile`, credentials and project ID never come from env, and a profile without credentials is `ErrNoCredentials`.
- The credentials file is refused before parsing when group or others can read it; explicit paths that do not exist are errors; FIFOs and directories are errors; no error carries a value.
- 401: the transport invalidates exactly the token it sent, compare-and-clear in memory and on disk; tokens younger than 30 seconds are not invalidated; parallel 401s cause at most one login; no authenticated request goes out without a token.
- Token cache: dir 0700 and files 0600 at creation; length-prefixed hash of the effective URLs and resolved profile; lock acquired without blocking and retried until `ctx` ends; lock files never deleted; a write failure after login still returns the token; malformed or unreadable cache is a miss.
- Windows and Unix lock builds both compile and share one interface.

### Task 1: `internal/ini` parser

**Files:** Create `internal/ini/ini.go`, `internal/ini/ini_test.go`.

**Interfaces:** `ini.Parse(name string, r io.Reader) (File, error)`; `type File map[string]map[string]string`; `(File) Section(name string) (map[string]string, bool)`.

Rules: strip a leading UTF-8 BOM; `[section]` headers (trim inside brackets); `key = value` (trim both; keys lowercased; value keeps inner spaces and `=`; no quote handling); blank lines skipped; full-line comments start with `#` or `;` after optional spaces; a key before any section, a line without `=`, an empty key, or an unclosed `[` is an error `"<name>:<line>: <reason>"` that includes no content from the line. A repeated key keeps the last value; a repeated section merges. Empty values are kept as empty strings (callers treat them as unset).

### Task 2: `CredentialsProvider` and the 401 fix

**Files:** Modify `internal/transport/transport.go`, `internal/transport/transport_test.go`, `internal/core/auth.go`, `internal/core/client.go`, `internal/core/client_options.go`, `internal/core/config.go`; create `internal/core/credentials_test.go`; modify `vngcloud.go`, `vngcloud_test.go`, `docs/wiki/Authentication.md`.

**Interfaces:**
- `transport.TokenSource` gains `Invalidate(accessToken string)`.
- `core.Token{AccessToken string; ExpiresAt time.Time}` (alias of `transport.Token`); `core.CredentialsProvider` interface `Token(ctx) (Token, error)` and `Invalidate(accessToken string)`; `core.WithCredentialsProvider(p) Option`; an unexported clock hook on the IAM token path, set from core tests (not a public option).
- Root re-exports `Token`, `CredentialsProvider`, `WithCredentialsProvider`.
- Credential options resolve as the design says: a provider wins over a static token, which wins over IAM User values. No error for setting several.

Transport behavior:
- `do` returns the exact access token it placed in the `Authorization` header for the final attempt.
- On a 401: under `refreshMu`, if the transport's current token equals the sent token, clear it and call `tokenSource.Invalidate(sent)`; then get a token (`refreshToken`) and retry once. If another goroutine already replaced the token, skip invalidation and retry with the current token. Never call `Invalidate("")`.
- A request with `SkipAuth` false is never sent without a token: if the token is empty after `EnsureToken`, return `ErrAuth` without sending.
- A provider returning an empty token with a nil error is `ErrAuth`. A zero `ExpiresAt` means the token is fetched on every request; document it on the interface.

IAM path (`auth.go`): keep the cached token with the time it was obtained. `Invalidate(sent)` clears the cache only when `cachedToken == sent` and the token is at least 30 seconds old (injected clock). Otherwise it does nothing, so the retry reuses the same token, the server returns 401 again, and the call ends with `ErrAuth`. Static token `Invalidate` is a no-op.

### Task 3: `internal/tokencache` and `WithTokenCache`

**Files:** Create `internal/tokencache/cache.go`, `lock_flock.go` (`//go:build linux || darwin || freebsd || netbsd || openbsd || dragonfly`), `lock_windows.go` (`//go:build windows`), `lock_other.go` (the remaining GOOS values: in-process mutex only, documented), `cache_test.go`. Modify `internal/core/auth.go`, `internal/core/client_options.go`, `internal/core/client.go`, `vngcloud.go`, `docs/wiki/Configuration.md`.

**Interfaces:**
- `tokencache.New(dir string, now func() time.Time) *Cache`.
- `(*Cache) Get(ctx, key Key, rejected string, login func(context.Context) (Token, error)) (Token, error)`: acquire the lock for `key` (non-blocking attempt, then retry with backoff from 10 ms up to 500 ms until `ctx` ends, returning `ctx.Err()`), read the file, treat it as a miss when missing, unreadable, malformed, expiring within 30 seconds, or holding `rejected`; on a miss call `login`, write the result, release the lock, return the token. A write failure (temp create, write, `Sync`, `Close`, `Rename`) removes the temp file and still returns the fresh token with a nil error.
- `tokencache.Key{Profile, RootEmail, Username, SigninURL, TokenURL string}`; `(Key) Hash()` is SHA-256 hex over each field as `<decimal length>:<value>` in that order.
- `core.WithTokenCache(dir) Option`, `core.WithProfile(name) Option`; root re-exports both. The key uses the effective sign-in and token URLs (`firstNonEmpty(auth override, resolved endpoint)`) and the resolved profile name (`LoadConfig` passes it even when it is the default).

Rules:
- `MkdirAll(dir, 0o700)`; on non-Windows, refuse a dir with group or other bits (error names the dir only).
- Token file `<dir>/<hash>.json` holds `{"accessToken":"...","expiresAt":"RFC3339","obtainedAt":"RFC3339"}`; the 30-second rule uses `obtainedAt`, so a token another process fetched 5 seconds ago is never invalidated, written through `os.CreateTemp(dir, ".tok-*")` (0600), `Sync`, `Close`, `os.Rename`.
- Lock file `<dir>/<hash>.lock`, 0600, never deleted. Flock build: `syscall.Flock(fd, LOCK_EX|LOCK_NB)`, retry on `EWOULDBLOCK`. Windows build: `syscall.CreateFile` with share mode 0 and `OPEN_ALWAYS`, retry on `ERROR_SHARING_VIOLATION`; close to release.
- Only IAM User credentials use the cache. Static tokens and providers never touch disk. Without `WithTokenCache`, nothing is written.
- IAM path order: memory, then `Cache.Get` (with the rejected token when called after a 401), then login.

- [ ] **Step 1: Failing tests** (fake clock, `t.TempDir()`): reuse within expiry; expiry at `expiresAt - 30s`; each key field change misses; hash boundary `{"ab","c"}` vs `{"a","bc"}`; malformed, empty, and mode-0000 files are misses (skip the 0000 case when `os.Geteuid() == 0`); dir 0700 and file 0600 on Unix; a pre-existing 0755 dir is an error without a token in the message; a file holding `rejected` is a miss and is replaced; two `Cache` values on one dir with 8 goroutines log in exactly once (`-race`); a held lock plus a 50 ms `ctx` returns `context.DeadlineExceeded`; a read-only dir after login still returns the token and leaves no temp file; core: two Configs with the same IAM credentials and `WithTokenCache` dir log in once; a static-token Config with `WithTokenCache` writes nothing.

### Task 4: `LoadConfig`, env vars, profiles, file safety

**Files:** Create `internal/core/load.go`, `internal/core/load_test.go`. Modify `internal/core/errors.go`, `internal/core/client_options.go`, `vngcloud.go`, `vngcloud_test.go`, `docs/wiki/Configuration.md`, `docs/wiki/Getting-Started.md`.

**Interfaces:** `core.LoadConfig(ctx, opts ...Option) (Config, error)`; `WithConfigFile(path)`, `WithSharedCredentialsFile(path)`; sentinels `ErrNoCredentials` and `ErrCredentialsFile`, each wrapping `ErrInvalidConfig` (`errors.Is` matches both). Root re-exports all of them.

Resolution:
1. Apply `opts`, recording which fields they set (non-empty values only).
2. Profile: `WithProfile` (explicit) else `VNGCLOUD_PROFILE` else `default`.
3. Paths: option, else `VNGCLOUD_CONFIG_FILE` / `VNGCLOUD_SHARED_CREDENTIALS_FILE` (both explicit), else `~/.vngcloud/config` and `~/.vngcloud/credentials` from `os.UserHomeDir` (default). A default path that does not exist is skipped; an explicit path that does not exist is an error. An unknown home with no explicit paths skips files.
4. Opening a file: `os.Lstat` then require a regular file after following at most the final symlink (`os.Stat` on the path must be regular); open; for the credentials file, `f.Stat()` on the handle and, on non-Windows, refuse `mode&0o077 != 0` with `ErrCredentialsFile` naming the path and `chmod 600`, before reading; a missing explicit path, permission denied, and other open errors are `ErrCredentialsFile` for the credentials file and `ErrInvalidConfig` for the config file, naming the path.
5. Sections: config `default` or `profile <name>`; credentials `<name>`. Keys: config `region`, `project_id`; credentials `root_email`, `username`, `password`, `totp_secret`. Unknown keys ignored. A non-default named profile found in neither file is `ErrInvalidConfig` naming it.
6. Region: option, else `VNGCLOUD_REGION`, else profile. Missing is `ErrInvalidConfig` (not a credentials sentinel).
7. Project ID: option, else (only when the profile is not explicit) `VNGCLOUD_PROJECT_ID`, else profile.
8. Credentials, one set from the first source that sets any value: options; then env (`VNGCLOUD_ACCESS_TOKEN`, `VNGCLOUD_ROOT_EMAIL`, `VNGCLOUD_USERNAME`, `VNGCLOUD_PASSWORD`, `VNGCLOUD_TOTP_SECRET`) only when the profile is not explicit; then the profile. With an explicit profile and no credentials from options or the profile, return `ErrNoCredentials` naming the profile. With nothing anywhere, `ErrNoCredentials` naming the sources checked. Within one source an access token wins over IAM values. A TOTP secret becomes `&SecretTOTP{Secret: ...}`.
9. Pass the resolved profile name to the token cache key, then build with `NewConfig` plus every non-credential option the caller passed.
