# Service-account authentication implementation plan

Ship SDK service-account authentication, configuration, cache, CLI support, and public docs together as one feature release after independent review and the manager's implementation repeats.

## Constraints

- Authorities: [accepted design](../design/service-account-auth.md), [API evidence and probe procedure](../design/service-account-auth-api.md), [routing](../../AGENTS.md#ai-agent-definitions-and-routing), [workflow](../../instructions/workflow.md), [testing](../../instructions/testing.md), [security](../../instructions/security.md), [live data](../../instructions/live-data.md), [Go](../../instructions/go.md), [documentation](../../instructions/documentation.md), [release](../../instructions/release.md), and [accepted ADRs](../adr/README.md). The owner approved all eight decisions; the design's remaining proposed-decision wording does not reopen them. Obtain independent plan review before implementation. Stop on a missing contract or conflicting authority instead of inventing one.
- The manager owns fixtures, briefs, worktrees, verification, live calls, Git, PRs, release notes, signed tags, and publication. Each code task uses `gpt-6.1-sol` medium through implementer. One separate `gpt-6.1-sol` xhigh code-review job reviews the complete release after Tasks 6 and 6a, including adversarial auth, token-handling, and credential-storage review, then confirms fixes. The ignored live-write harness also needs its own separate `gpt-6.1-sol` xhigh pre-run review and fix confirmation in Task 6a. Reviewers never implement fixes or review their own work. Failure investigation and fixes use `gpt-6.1-sol` xhigh through troubleshooter.
- Run tasks in order. Start each worker with `git status --short` in a credential-free owned worktree with the [CLAUDE.md sandbox settings](../../CLAUDE.md#claude-routing-and-invocation). Workers are not alone and preserve others' edits. Workers never change Git state, read `.env`, private example configs or `examples/basic/output/`, fetch dependencies/tools, or call the live API. Each concurrent writer needs a separate worktree and disjoint paths; at most three workers run across all slices. The manager inspects each diff and reruns required checks before dependent work.
- Sequence shared-file implementation after the pricing volume/storage release lands. Local `git log --all` identifies pricing commit `2b545f3` on `wip/pricing-volume-storage`, touching `internal/core/auth.go`, `internal/core/client.go`, `internal/transport/transport.go`, and `internal/tokencache/cache.go`, plus their shared tests. This worktree predates those changes. The manager refreshes the implementation base and briefs the landed behavior before Task 3; never run competing writers on those paths. Preserve pricing's post-lock context checks, guarded discovery responses, single-flight token identity, and cancellation checks before committing results. Any behavior-changing conflict resolution needs independent review.
- Keep the SDK standard-library only, public imports stable, root `vngcloud` free of service imports, and the existing `Secret` type in `secret.go`. Use a private immutable redacting credential snapshot; do not expose a token getter, token endpoint, public test hook, scope option, login command, automatic policy grant, cache-clear command, or auth flag.
- Preserve IAM-user hashes and behavior, provider/static cache exclusion, project ambiguity, vCDN key independence, product endpoints, IAM guards, paid-write gates, `Once`, and NAT create/delete's IAM-user/Hanoi restriction. Service-account authentication must report false from `UsesIAMUserLogin`; NAT quotes keep their existing wider auth and region support.
- Fixed-host JSON/Basic exchange and the recorded security-group scope are verified. SDK-owned authentication and secret-bound cache isolation still need deterministic tests and manager repeats. Server scope/enumeration, other services/regions, activation, deletion revocation, expiry-wait behavior, lifespan extrema/zero semantics, issuance limits, and universal secret lifetime stay deferred. No paid server, broader policy, or revocation claim enters this release.
- Use one line per paragraph or list item, unpadded tables, no dates or em dashes, and at most 450 lines. Do not put plan, task, or review IDs in code, tests, comments, wiki pages, or other living docs. Human docs wrap at 80 columns; generated pages change through their sources.
