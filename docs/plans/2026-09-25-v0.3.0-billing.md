# v0.3.0 Billing and Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. One final review after the last code task, not one per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the shared `vngcloud.Config` and the first two public service packages, `billing` (budgets, thresholds, alerts, cost, balances) and `pricing` (price quotes), so spend can be capped and priced before any paid write. The other services stay behind the transitional `vngcloud.NewClient` until v0.4.0.

**Architecture:** Task 1 makes `core.Config` an opaque handle around one `*core.Client`. `billing/` and `pricing/` are new top-level packages built on it with `New(cfg vngcloud.Config) *Client` and `Method(ctx, *Input) (*Output, error)`. Billing calls go to a new global `Billing` endpoint (the dashboard host root); quotes go to the regional billing gateway that `endpoints.Set` names `Portal`. The transport gains write safety from ADR 0002 before the first write lands.

**Tech Stack:** Go 1.27.1, standard library only, golangci-lint 2.13.2.

**Spec (owner-approved 2026-09-25):** `docs/design/billing.md` (all of it), `docs/adr/0002-write-api-conventions.md`, and `docs/design/sdk-and-cli.md` sections "SDK" and "Releases". Design wins over this plan; stop and report a conflict.

## Global Constraints

- Work on branch `v0.3.0` from `master`. The manager creates it and makes every commit; workers do not run git write commands.
- Every commit passes `make check` (tests, vet, golangci-lint at 0 issues, Markdown ≤ 450 lines, non-test Go ≤ 700 lines).
- Standard library only. No new dependencies in `go.mod`.
- Root `vngcloud` never imports a service package; `internal/core` never imports root. `billing` and `pricing` import root only for `vngcloud.Config`, and tests may import root.
- Operation signature `func (c *Client) Op(ctx context.Context, in *OpInput) (*OpOutput, error)`. Every operation has its own Input type, even when empty. A nil `in` is valid when no field is required.
- Input and Output structs have no JSON tags. Resource models keep API JSON tags. Update Inputs use pointer fields (ADR 0002).
- Each operation calls `core.CheckRequired("<pkg>.<Op>", in)` first, then `core.CheckPathID` for every ID it puts in a path and `core.CheckDate` for every date, all before any request.
- `transport.Request.Operation` is `"<package>.<Method>"`: `"billing.ListBudgets"`, `"pricing.GetQuote"`.
- Fixtures live in `testdata/billing/` and `testdata/pricing/`, sanitized per `instructions/live-data.md`. Never write account data (emails, usernames, project IDs, real UUIDs, balances, costs) into code, tests, fixtures, or docs. Synthetic values such as `budget-1` and `1000000` are fine.
- Code comments explain constraints only. No plan or task IDs in code, tests, or docs.

## Review Focus

The final review is adversarial for Tasks 2, 5, and 7 (transport retry, budget writes, live write test).

- A `POST` create is never retried after a 5xx or a network error that may have reached the server; it is retried after a 429 or a dial failure. `PUT`, `DELETE`, and `GET` keep today's retry.
- Every write path ID passes `^[A-Za-z0-9-]+$` before a request; `..`, `.`, `/`, and empty are rejected with `ErrInvalidInput`.
- `UpdateBudget` and `UpdateBudgetThreshold` send only non-nil fields.
- An HTTP 2xx whose envelope `code` is outside 200 to 299 is an `*APIError`; a null `code` is success. Creates return code 201.
- `Budget not found` and `Threshold not found` 400s map to code `NotFound` wrapping `ErrNotFound`, in `billing` only.
- No token, recipient address, or amount appears in an error message.
- The live write test cannot leave a budget behind and cannot send an alert.
- `vngcloud.IsRetryable` is true only for a request the transport itself would retry.
- From Task 1: a zero `vngcloud.Config{}` fails with `ErrInvalidConfig`, never a panic; two clients from one Config discover the project once under `-race`; a static-token Config never logs in.

### Task 2: Transport write safety, envelope code, input checks, `vngcloud.Ptr`

**Files:** Modify `internal/transport/transport.go`, `internal/transport/transport_test.go`, `internal/core/required.go`, `internal/core/required_test.go`, `internal/core/client.go`, `internal/testutil/testutil.go`, `vngcloud.go`, `vngcloud_test.go`.

**Interfaces:** Produces `transport.Request.Idempotent bool`; `core.CheckPathID(op, field, value string) error`; `core.CheckDate(op, field, value string) error`; `vngcloud.Ptr[T any](v T) *T`; `transport.APIError.Code` holding a numeric envelope code in decimal form; `core.Client.DoJSONStatus(ctx, req, out) (int, error)`, which is `DoJSON` that also returns the final HTTP status (`DoJSON` calls it); `testutil.NewRetryConfig(t, handler) core.Config`, like `testutil.NewConfig` but with `RetryCount: 3` and a 1 ms `RetryInterval`, so service tests can prove what is and is not retried (`NewConfig` keeps `RetryCount` 0).

Rules (ADR 0002 decision 2):
- A request is idempotent when its method is `GET`, `HEAD`, `PUT`, or `DELETE`, or when `Idempotent` is true. `POST` and `PATCH` default to not idempotent.
- An idempotent request keeps today's retry behavior exactly.
- A non-idempotent request is retried only after HTTP 429, or after a transport error that is a dial failure (`errors.As(err, &opErr)` with `opErr.Op == "dial"` for `*net.OpError`). After any other error or a 502/503/504 it returns at once.
- The 401 re-login retry in `DoJSON` stays for every method: a 401 means the server rejected the request before acting.
- `APIError.Retryable` matches what the transport would do: true only when the request is idempotent and the status or error is retryable, or the status is 429, or the error is a dial failure. A `POST` that got a 502 or a read error returns `Retryable: false`.

  - `TestIdempotentPostRetried`: same with `Idempotent: true`; four calls.
  - `TestPostRetriedAfter429`: 429 then 200; two calls; success.
  - `TestPutRetriedAfter502`: 502 then 200; two calls; success.

Envelope helper in `billing.go`: `func (c *Client) do(ctx context.Context, req transport.Request, out any) error` calls `core.Client.DoJSON` into `struct{ Code json.RawMessage; Message string; Data json.RawMessage }` (JSON tags `code`, `message`, `data`). It calls `DoJSONStatus`. A non-null `code` other than `200` returns `&core.APIError{Operation, StatusCode: <actual HTTP status>, Code: <decimal>, Message}`; a null `code` keeps `Code` empty. Then it unmarshals `Data` into `out` when `out` is non-nil and `Data` is not null. On an error from `DoJSONStatus`, and on an envelope error, `mapNotFound` turns a `*core.APIError` with status 400 whose message starts with `Budget not found` or `Threshold not found` into code `NotFound` with `Err: core.ErrNotFound`, keeping status 400.

Model fields (API JSON names from the console; the live capture in Task 7 confirms them):
- `Budget`: `uuid`, `id` (int64), `name`, `periodType`, `type`, `limitAmount` (int64), `status`, `actualCost`, `forecastedCost`, `actualPercentage`, `forecastedPercentage`, `thresholdPercentage` (all `*float64`).
- `PeriodCost`: `periodKey`, `periodStart`, `periodEnd` (strings), `actualCost`, `forecastedCost` (float64).
- `Threshold`: `uuid`, `thresholdType`, `thresholdPercentage` (float64), `comparisonOperator`, `enabled`, `maxAlertsPerPeriod`, `reminderIntervalHours` (int), `notificationState`, `lastAlertAt` (string).
- `Alert`: `triggeredAt`, `thresholdType`, `thresholdPercentage`, `triggeredValue`, `actualPercentage`, `deliveryStatus`, and `recipients`, a JSON string holding an array. `Alert.UnmarshalJSON` decodes it into `Recipients []string`; when that fails, `Recipients` stays nil and `RecipientsRaw` keeps the string.
- `Balances`: `cash`, `poc`, `cashAvailable`, `cashHolding`, `pocHolding`, each `*float64`, decoded by a helper that accepts null, a number, or a numeric string. `expiresPoc` is not decoded. The response is enveloped today (live-verified); when a body has neither a `code` nor a `data` key, `GetBalances` decodes the whole body instead.
- Cost overview output: `Summary` (`currentCost`, `lastPeriodCost`, `changePercent`, `forecastCost`, `activeCount`, `breakdown` as `[]CostBreakdown{Key string; Cost float64}` if the fixture shows that shape, else leave `breakdown` out and report), `Series`, `Interval`, `StartDate`, `EndDate`, `GroupBy`. Input rules from the design: `ListBudgets` sends `view=summary` and `status` when set. `ListBudgetAlerts` sends `periodKey` when set. Cost operations require `StartDate` and `EndDate` (checked with `CheckDate`), send `groupBy` default `product` and `interval` default `daily` for the overview, and send `product`, `resourceType`, `resourceId`, `q` only when set.
