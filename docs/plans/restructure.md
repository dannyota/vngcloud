# Restructure implementation plan

**Goal:** Adopt Ricevanta's governance, document classes, decision register, and reviewed-slice workflow while preserving vngcloud's public Go import paths, CLI, wiki generation, release tags, release notes, and security checks.

**Architecture:** AGENTS.md routes readers by question and activity. Shared instructions own work rules; four agent definitions own duties without static path assignments. Domain designs own rules, specs own mechanism contracts and evidence, decisions own approved choices, retained plans own execution, and TODO.md owns short-term work. The module stays `danny.vn/vngcloud`, with public services at the root and private implementation under `internal/`.

## Global constraints

- Checkboxes record completed work. Keep finished plans under `docs/plans/`; remove a TODO line in the commit that completes it. Do not cite plan names, task IDs, or review finding IDs in code, comments, tests, or living docs.
- Stage 1 is context only. Public NAT writes are in `.claude/worktrees/nat-writes`, on paths `network/`, `internal/core/`, `testdata/network/`, `livetest/`, `docs/wiki/Network-NAT.md`, `docs/wiki/CLI-Network.md`, and `internal/cli/`. Stage 2 forbids edits to all those paths and never enters that worktree. Stage 3 and Stage 4 wait until the NAT release is on master with green CI on its tagged commit.
- The owner approved the direction and routing, landing, commit, and plan-retention choices stated here. This plan does not approve a live API call, purchase, cleanup, credential read, or root-checkout NAT implementation. Never read `.env`, private example config values, or `examples/basic/output/` into context. The repository, wiki, and CI logs are public.
- Claude designs, researches, and coordinates only. Fable high writes designs through `designer`; when unavailable, `gpt-6-astra` high writes designs in a general-purpose worker. `gpt-6.1-sol` medium writes all code, scripts, workflow changes, and small code edits. `gpt-6-luna` low may explore or perform mechanical non-code work. No worker or subagent runs on Sonnet or Opus. The owner chooses the main Claude Code session model without this restriction. Set model and effort on every worker or subagent dispatch.
- Every review and fix confirmation uses xhigh on the other model: `gpt-6-astra` reviews Sol code and Sol-authored plans; `gpt-6.1-sol` reviews Astra designs. Fable or human work goes to whichever reviewer is free. A design author never implements that slice, and a reviewer never fixes reviewed files. Task reviews below include fix confirmation under the same rule.
- The primary agent owns planning, briefs, worktrees, verification, Git, releases, and reports. At most three workers run across slices, including designers and reviewers; nested workers count toward that cap. Each concurrent writer gets a separate worktree and disjoint paths. Workers are not alone, must preserve others' edits, and never change Git state. Each brief names authorities, exact owned and forbidden paths, checks, done criteria, and report format.
- Start each task with `git status --short`. Stop on overlapping ownership, conflicting authority, or an unresolved contract. The manager inspects every diff and runs required checks before accepting reports. Reports list new, changed, and deleted files, exact checks and outcomes, skipped checks and reasons, and open items.
- Keep `make check`, including its existing race-test target; do not copy Ricevanta's lighter local-test policy over it. Run `make check` before every commit. Keep the 700-line non-test Go cap, the 450-line general Markdown cap, generated-page exemptions, standard-library-only SDK, scanner gates, tool pins, signed commits and tags, and staged-content hook.
- Use plain words, active voice, short paragraphs, and no em dashes or dates. Agent-only files use one line per paragraph or list item and unpadded tables; human docs wrap at 80 columns. Designs and specs must finish at 400 lines or fewer. Split along sections and preserve information. Release notes retain versioned release facts; do not turn living designs into release history.
- Only the manager lands changes. Each slice has `.claude/worktrees/<slice>` and `wip/<slice>`, a pushed branch, and a PR against master. Inspect the full log and diff; land only a descendant of current master whose every triggered workflow passed for the exact PR head. `git push origin <head>:master` uses the owner's approved admin bypass. Never force-push or delete master. Rebase a stale slice, review behavior-changing conflict resolution, and rerun CI on the new head before landing.
- Commits have a plain imperative subject and a body explaining why, plus the owner's DCO sign-off from `git commit -s` and SSH signature. No Conventional Commit prefixes or tool attribution. Stage exact paths; never force-add, stage secrets, change global ignores, disable signing, or rewrite pushed commits except an explicitly coordinated `wip/` rebase with `--force-with-lease`. Tags require green CI on the exact commit; governance and document-only slices need no feature tag.

## Review focus

- Preserve every security invariant and live-run restriction while removing duplicated instructions. No routing escape lets Claude or Luna implement code, and no reviewer edits the slice it reviews.
- Trace leaked tokens in logs or errors, hostile or malformed API responses, redirects or endpoint overrides to foreign hosts, tampered profiles or token caches, and concurrent or repeated paid writes. Cover credential files, debug output, captures, retry boundaries, price races, partial output, and cleanup authority.
- A PR merge-ref result is not evidence for the PR head. A skipped, cancelled, missing, or pending required run is not success. Publishing Wiki stays isolated from PR code and its read-only validation.
- Preserve contract details, API provenance, evidence limits, owner exceptions, and unresolved gates. Neither a move nor an approval entry upgrades an inferred schema to live-verified evidence.
- Account-specific notes never move into public TODO or analysis. Decision conversion must resolve superseded choices without inventing approval. Comment rewrites must change no Go tokens, test names, gates, or behavior.
