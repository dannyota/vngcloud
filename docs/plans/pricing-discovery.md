# Pricing discovery implementation plan

Ship monthly volume and storage discovery with response-security groundwork, then reference-configuration compute discovery, then public-IP discovery, with one feature per tag.

## Constraints

- Authorities: [accepted design](../design/pricing-discovery.md), [API evidence](../design/pricing-discovery-api.md), [routing](../../AGENTS.md#ai-agent-definitions-and-routing), [workflow](../../instructions/workflow.md), [testing](../../instructions/testing.md), [live data](../../instructions/live-data.md), [security](../../instructions/security.md), [Go](../../instructions/go.md), [documentation](../../instructions/documentation.md), [release](../../instructions/release.md), and the [accepted ADRs](../adr/README.md). Obtain independent plan review before code. Stop on conflicting authority or missing wire evidence; never infer a populated schema from an empty array.
- The manager owns fixtures, briefs, worktrees, verification, live checks, Git, PRs, release notes, signed tags, and publication. Every code task uses `gpt-6.1-sol` medium through implementer. A separate `gpt-6.1-sol` xhigh code-review job reviews each release once after its last code task and confirms fixes. Response security and token handling require adversarial review. Reviewers never fix reviewed source. Troubleshooting uses `gpt-6.1-sol` xhigh through troubleshooter.
- Run tasks in order. Use credential-free writer worktrees with brief-owned paths and the sandbox settings in [CLAUDE.md](../../CLAUDE.md). Preserve others' edits; start with `git status --short`. Workers never change Git state, read `.env`, private example configs or `examples/basic/output/`, fetch tools or dependencies, or make live calls. At most three workers run across all slices; each concurrent writer needs a separate worktree and disjoint ownership.
- The manager inspects each task's diff and reruns required checks before dependent work. Tasks 2 and 3 form the first release on `wip/pricing-volume-storage`; Task 4 uses `wip/pricing-compute`; Task 5 uses `wip/pricing-network`. Each release uses a master-targeting PR, current-master ancestry, independent fix confirmation, resolved Copilot findings, and every triggered validation workflow green on the exact head under [landing](../../instructions/workflow.md#landing-a-slice). Missing, skipped, cancelled, pending, failed, or merge-ref runs do not establish success. Tag only the exact eligible landed commit; complete post-landing CI and notification handling before the next release.
- Preserve public imports, existing model fields and JSON tags, generic quotes, paid-write guards, retries, endpoint overrides, token identity, and project ambiguity. The SDK stays standard-library only; root `vngcloud` imports no service package. New private readers must apply discovery security and limits to auxiliary reads too; wrapping an unchanged public read after decoding cannot satisfy the response guard.
- Monthly-only inputs have no `Periods` or term projection. GiB fields remain nil until first-party byte evidence exists. Bandwidth routes, units, tariffs, capacity fields, and period comparison stay deferred. Populated custom, legacy, partner, or GPU branch decoding stays gated on matching sanitized fixtures; empty custom arrays prove no populated schema. No orders, provisioning, inventory, eligibility reads, NAT quotes, or account-data calls enter discovery.
- Use one line per paragraph or list item, unpadded tables, no dates or em dashes, and at most 450 lines. Do not put plan, task, or review IDs in code, tests, comments, wiki pages, or other living docs. Release notes remain manager-owned.
